# Implementation coverage

What Graphite does today, how each part is verified, and what is still missing. `OBJECTIVE.md` describes the complete product; this file tracks progress toward it. Update it with every change that adds, removes, or re-verifies behavior.

Last updated: 2026-10-06.

## A quieter interface and a phone layout: 2026-10-06

At the owner's request, after Obsidian's Minimal theme: the interface and the Pencil bar felt cluttered, and the iPhone layout unconsidered. The eighth increment of `Premium-experience-plan.md` lists the changes; `Architecture.md` describes them under the shared document controls and the fixed tool bar.

- One Write toggle (`DocumentModeToggle`) replaces the segmented Read/Write control in notes, PDFs and canvases, in the toolbar, the tab bar and the control row. Show/Hide Tools left the PDF's toolbar and tab bar for a Show Pencil Tools switch in its More menu.
- Bars take the page's color with a hairline; tabs are muted names with a faint fill for the tab in use and a close button on that tab and under the pointer; the empty tab is a column of links that fits a phone; folder icons, the vault bar and the keyboard toolbar's icons are muted; sidebar rows are denser.
- Headings have one scale and weight in Live Preview, Source mode and Reading view (`HeadingTypography`); the inline title is semibold.
- Compact widths: the document comes first and the file list is a step back; no tab bar; a bottom bar with back, forward, the quick switcher, a new note, the tab switcher (`TabSwitcher`) and the command palette; the navigation bar holds only the document's controls; a PDF hides the bottom bar while the palette is docked; the quick switcher keeps its results above the keyboard.
- The fixed bar and the squeeze palette draw each tool standing upright with its tip in the ink's color, the tool in use raised (`PencilToolGlyph`).

The two commits that made these changes were written in a Linux container without Xcode or a Swift compiler: they were parsed with tree-sitter and reviewed by reading, nothing more. The same day they were built, run and corrected on a Mac (Xcode 27.0, macOS 27.0) and in iOS 27.0 simulators, an iPad Pro 11-inch (M5) and an iPhone 17 Pro, with a copy of `Tests/test_vault` (its lecture notes and PDFs, without the videos). No iOS 18 simulator runtime is installed, and no physical device was used.

- Builds: the package and the app built as committed, with no errors and no new warnings. SwiftPM's build folder has to be outside the iCloud-synced Desktop (`swift build --scratch-path …`): in the repository's `.build`, codesign refuses the resource bundles for their extended attributes.
- `swift test`: 1,613 tests in four bundles, none failing and one skipped, the three updated tests among them. `UiEditorMacEditorTests.testHeadingJumpWaitsForAWindowThenSelectsAndScrollsToTheHeading` failed once on this branch and once on `main` (e29dcc6), and passed on the next run: it depends on timing.
- `GraphiteIntegrationTests`: on the iPad simulator, 189 of 189 as the two commits left them, and 190 of 190 after the fixes below (one test added). On the iPhone simulator, three canvas tests and the equation-number test failed, on `main` as well: they were written for an iPad's width. The canvas tests now skip on a phone, saying why, and the equation test runs only its narrow case there; those suites then ran 14 tests, 3 skipped, none failing.
- Seen in the simulators, light and dark: the Write toggle reads as on (accent pencil on a faint fill) and off (muted pencil) in the iPad tab bar, and as a filled accent circle in the iPhone's navigation bar; headings measure the same width in Read and Write; the iPhone opens on the document, not the file list, and choosing the file already open, after going back to the list, shows it again; the bottom bar hides while a PDF's palette is shown and comes back when Show Pencil Tools is turned off; Go to Page in the PDF's More menu opens its sheet on the iPhone and goes to the page; the quick switcher's results end above the software keyboard; the tab switcher lists, switches and adds tabs.

Fixed after running it:

- The iPhone's navigation bar had no room for the document's controls: beside the editable title and the always-present Record button, iOS put Write and More, and for a PDF Undo and Redo, into an overflow menu, where Write was a checked item and Undo a submenu. The title is now a plain one that truncates, Rename is in More, and the Record button shows only while there is a recording to follow; a recording starts from the command palette.
- The iPhone's file list was the iPad sidebar drawn as inset cards with separators, a blurred large title under the panel picker, a segmented picker cutting off "Bookmarks", and the vault bar above the search field. The file list on both is now drawn as Obsidian's file explorer (chevrons before folder names, indents with guide lines, no icons or separators, extensions muted after names), the panel picker shows symbols, and on a phone the list is plain, its inline title switches vaults, and the vault bar is gone.
- A note with an embedded PDF raised the note's keyboard toolbar as it opened, with nothing being typed: PDFKit makes the embed's document view first responder, which inherits its ancestor's input accessory. The PDF view now has an empty one.
- On a phone the keyboard toolbar stood over the bottom bar while typing with a hardware keyboard; the bottom bar now gives way while the keyboard is up or a note takes typing.
- The inline title showed `.md`; it is the name without it, as Obsidian's is.
- The text moved about 15 points sideways when a note switched between reading and writing: the reading view's column was 760 points with 28 beside it, Live Preview's text 730 with 33. The reading view now uses Live Preview's numbers; the same heading starts at the same place in both.
- Switching between reading and writing showed each view where it had last been itself, so a note read halfway down opened for writing at its top. Each view now starts where the other was: seen in the iPad simulator in both directions on a lecture note, to within the part of a callout scrolled away; `testEveryBlockKnowsWhereItStartsInTheBody`, `testTheReadingViewKnowsWhichCharacterOfTheNoteIsAtItsTop` and `testSwitchingBetweenReadingAndWritingKeepsThePlace` cover where blocks start, the character at the top and the hand-over.
- PDF ink was drawn at the page's size and magnified by the zoom: soft at every zoom above 1, which includes a page fitted to an iPad's width in portrait, with PencilKit's tile edges showing when zoomed in. Page canvases now draw at the zoom they are seen at, up to three times the page's size, and a stroke stays as wide on the page as at any other zoom (`Architecture.md`, PDF Pencil). Checked in the simulator by drawing, zooming and comparing pixels, and by `PencilWorkspaceTests.testPageInkIsDrawnAtTheZoomItIsSeenAtAndStaysInPagePoints`; `InkSelectionTests` and `PicturesAndPaperTests` were adjusted to the canvas's zoom and the guides' new place.

Not established: how the sharper PDF ink, and writing while zoomed, look and feel with a real Apple Pencil on the iPad, and the memory a page full of ink takes at a rendering scale of 3 (the simulator does not report PencilKit's tiles); the toggle and the toolbars on iOS 18; large Dynamic Type sizes and VoiceOver for the changed views; landscape and Split View widths of the iPad. Read mode draws PDF ink 16 to 29% heavier than Write mode (measured in the simulator; older than this change). Hold-to-shape (0.45 seconds at rest after 24 points) is unchanged and still has to be judged with a Pencil.

## Bug hunt: 2026-09-30

This audit added reproductions before fixing confirmed failures. The fixes cover:

- Markdown edits lost during asynchronous Reload or Save a Copy, queued insertions omitted by saving before the editor updates, stale formatting commands consuming queued text, and command selections moving past their closing markers. Copies preserve their earlier snapshot while newer work remains open. Native queued-save Undo is exercised on macOS and in the iPad app (`MarkdownSessionConcurrencyTests`, `UiEditorMacEditorTests`, `EditingContinuityTests`).
- An older recorder's encoding error abandoning a newer recording, and Stop or an encoding error racing a delayed Resume. Synthetic delayed recorder tests verify a single resume, deferred stop, retained recovery audio, and recovery actions remaining unavailable during the ownership transfer (`AppleRecordingAccessRecordingTests`). Microphone permission cancellation now checks its start attempt after awaiting permission; the actual permission prompt and audio hardware remain device validation.
- Unreadable global or view-local Bases filters broadening the results. These now yield no rows, no vault-record loading, and an actionable explanation. Missing named views report which fallback is shown (`BaseQueryTests`, `UiBasesDocumentModelTests`).
- Bases YAML writes stripping custom tags or expanding anchors and aliases into detached copies. Rewritten entries now keep their tags, anchors, aliases and flow style (see "Bases: column widths, map tiles, html(), Kanban"), and an output that still cannot preserve them, such as a tag whose name cannot be written back, is refused (`BaseDefinitionEditorTests`, `CoreBasesEdgeCaseFixTests`, `CoreBasesDefinitionQueryFixTests`, `UiBasesDocumentModelTests`).
- Task search losing indented and lazy continuation text, reading task-shaped source in code/frontmatter, an empty task consuming the next completed task, and a quoted thematic break hiding its tasks as if they were frontmatter. Null-property searches no longer treat empty lists as null (`CoreSearchQueryFixTests`, `SearchSyntaxTests`). Compatibility reference: [Obsidian Search](https://obsidian.md/help/plugins/search).
- Template offsets using a different calendar time zone from formatting, producing a one-hour shift across daylight-saving changes. Extreme offsets also crashed through integer overflow. Offsets now use the requested zone, checked arithmetic, and a 10,000-year bound; an unrepresentable placeholder is left as written (`TemplateTests`, `MomentDateFormatTests`).
- Updating a property-type assignment overwriting an unreadable non-object `types` entry in `.obsidian/types.json`. Such updates now fail with the original bytes intact (`CoreFilesSettingsFixTests`). Bases `inFolder` now respects path case and boundaries, and `duration("")` returns null while invalid nonempty durations still report an error (`BaseEvaluatorTests`).
- The iPhone app run caught the new ink-selection resize frame exceeding the requested width. Resizing now corrects against rebuilt stroke render bounds before committing one history step. Hosted ink-selection tests pass on the iPhone simulator, including resizing, saved ink, and Undo (`InkSelectionTests`). The resize regression asserts the requested frame width and stroke breadth; an arbitrary fixed upper limit on the scale factor was removed because the canvas-to-screen scale changes that factor.

Final validation: the complete macOS suite executed 1,236 tests, with zero failures and one optional measurement skipped (`UiBasesReloadMeasurementTests`). The iPad Pro 11-inch (M5) simulator app suite passed 105 tests, including queued-save Undo and the resize correction. That iPad run preceded the last two task-search corrections and the resize test's scale-limit correction. The final iPhone 17 simulator suite passed 106 tests after those changes. Both simulators use iOS 27.0. The final two search reproductions also passed in the 26-test search run and the full macOS run. A fresh iPhone simulator initially failed to launch the test host before boot and data migration completed; the successful final run used that simulator after explicitly waiting for readiness. Its temporary device was removed afterwards. Test logs and result bundles for this audit are under `/tmp/graphite-bug-hunt-*`.

This audit does not establish that the application has no bugs. Physical Pencil and microphone behavior, real file-provider conflicts, and the outstanding behaviors below remain unverified or incomplete.

## Second bug-hunt pass: recovery and deep links

This follow-up reproduced and fixed five additional defects:

- Different recovery snapshots taken within one millisecond overwrote the earlier version. Snapshot publication now checks absence under file coordination and uses sequence suffixes, retaining the original date and newest-first order.
- Renaming a note into a path with existing recovery history discarded source snapshots with matching filenames. History merges now publish all source versions before removing the source folder, preserving both histories and the order of same-date source versions.
- Overlapping background snapshot calls bypassed the minimum interval. Eight concurrent calls reproduced eight copies despite a five-minute interval. Copies of the recovery store now share a mutation lock covering the interval check and mutation; the same test produces one copy. Forced concurrent copies with interval zero retain all eight versions (`FileRecoveryTests`).
- Deep-link appends inserted an extra blank line after CRLF and introduced LF into notes using CRLF or CR. Appends now inspect Unicode scalars and preserve the existing separator (`VaultURITests`).
- Creating a note through a deep link when its name was already taken saved the uniquely named file but left it out of the sidebar. This branch now refreshes the directory after publication (`UiWorkspaceModelFixTests`).

Verification: 60 targeted macOS tests passed across recovery, deep links, workspace operations and index scan batches. The final complete macOS run executed 1,396 tests with zero failures and one optional measurement skipped. The generic iOS Simulator app build also succeeded for arm64 and x86_64. These new regressions were exercised on macOS; this pass did not run hosted iPad/iPhone interaction tests. The initial full run recorded one canvas timing failure during a simultaneous iOS build (11.498 ms per frame against an 8 ms limit); the complete rerun passed that check at 1.565 ms per frame. Other work in the shared checkout added tests between those full runs. ## Display math: colored rank formula regression

The reported `$$ \color{#7852ee} … \operatorname{rank}(A^{T}A)=r. $$` fell back to raw source because the native typesetter rejected `\operatorname`. Rendering preparation now converts unstarred operator names to upright text and scoped color declarations to explicit color groups. Formula renderers honor explicit colors. Markdown files are not rewritten.

Verified on macOS on 2026-09-30: 29 targeted tests passed across `AppProjectTextualPatchTests`, `CorePreviewTypesetterCompatibilityTests`, `CorePreviewLaTeXTests`, and `CorePreviewDisplayMathTests`, using `swift test --build-system native` after the default build system hit an iCloud resource-signing failure. The exact reported formula was tested as both one-line and multiline display math, through preparation and Markdown parsing into a display attachment, then rendered to an image. Pixel checks confirmed purple ink across both halves; the rendered image was visually inspected. Nested color scopes and escaped braces are covered.

The Graphite app also built successfully for the generic iOS Simulator destination with signing disabled and derived data outside the repository.

Remaining limits: this is not full MathJax compatibility. Upright operator names do not reproduce all operator spacing rules; starred operators and their limit placement remain unsupported. This regression has not yet been exercised interactively in an iPad note.

## How to run the checks

The repository sits in an iCloud-synced Desktop folder. iCloud adds extended attributes that make code signing of test bundles fail, so build outside it:

```bash
swift test --scratch-path /tmp/graphite-build
```

iPad-only tests (PencilKit) run on a simulator through the app project. The Graphite scheme's `GraphiteIntegrationTests` target compiles and runs six files of `Tests/GraphiteAppleTests` (`InteroperabilityTests`, `PencilDrawingTests`, `PDFAnnotationTests`, `PDFPencilInkTests`, `VaultLocatorTests`, `VectorDrawingTests`) plus `AppIconBundleTests`, `PencilWorkspaceTests`, `EditingContinuityTests` and `PDFInkHistoryTests` from `App/Tests`, so copying the package outside the project (the `Graphite-Package` scheme) is no longer needed for them:

```bash
xcodebuild -project Graphite.xcodeproj -scheme Graphite -destination 'platform=iOS Simulator,name=iPad Pro 13-inch (M5)' test
```

The other files of `Tests/GraphiteAppleTests` are not in that target, so their UIKit-only tests (`testSecondEraserCutInsideAStrokeIsConvertedAgain` and `testDeferredRecordIsWrittenOnceByTheTracker` in `ApplePdfFixTests`) run nowhere yet.

Full-suite results (2026-09-25, after the bug-fix merge): `swift test` on macOS ran 1,117 tests: 1,116 passed and one was skipped (`UiBasesReloadMeasurementTests.testMeasureRepeatedReloadOfLargeBase`, which measures only when `GRAPHITE_MEASURE_BASES` is set). By target: 568 core, 127 index, 123 Apple, 299 UI. The app also builds for iOS (`xcodebuild -project Graphite.xcodeproj -scheme Graphite -destination 'generic/platform=iOS Simulator' build`). At that point, no test had run on an iPad simulator or a device after the merge: the iPad-only tests above were last run before the search and editing changes of 2026-09-23 (evening) and need a fresh run, and the iOS-only code the merge changed is verified only by that build (see "Implemented but not yet verified").

## Undo continuity and workspace controls: 2026-09-30

Notes keep their undo history when their tab is hidden, moved to the other side, or switched to reading view and back: the workspace keeps the native editors of the three most recently hidden notes (`MarkdownEditorRetention`, at most 2,000,000 UTF-16 units together, none after a memory warning). Each PDF has its own undo history, owned by its session, covering Pencil ink, markup, and page changes (rotate, move, duplicate, insert paper, import, delete). It survives page canvases being released and the view being rebuilt, and never mixes two PDFs. Undo and Redo sit just before Read/Write in every workspace; when the documents area is narrower than 1,100 points they move with Read/Write to the row below the tab bar, because the toolbar's overflow menu drops a segmented control.

Fixed later on 2026-09-30: closing the other side of the split left the note's pane empty until Read and then Write were tapped. With the cursor in the note, the same steps left both sides about half as tall as the window when the split opened, and quit the app when it closed. SwiftUI makes a note's new view before it dismantles the old one, and when the split closes it also makes a second view that it dismantles at once. The text view used to move to each new view as it was made, so it ended in the view that was dismantled; moving it then also took the keyboard from it in the middle of SwiftUI's update. It now stays in the view that shows it until that view is dismantled, and moves to the newest view of the note that is left. After such a move each typed character was also recorded twice, because the editor began following the text again without having stopped; that no longer happens.

## Tables fit the note: 2026-09-30

Reported by the user from a lecture note: a table with a figure in each of three columns showed every image at its full size, so the table was about three notes wide and scrolled sideways, where Obsidian shows the three figures side by side. An image in a table cell was sized to the whole note, not to its column, and a table never adapted to the note's width.

A table now fits the note as it does in Obsidian (see "Tables fit the note" in `Architecture.md` and patch 7 in `Vendor/textual/GRAPHITE-PATCHES.md`). This also changes tables of text alone: a table wider than the note used to keep every cell on one line and scroll sideways; it now wraps its text, and scrolls only when its widest words and formulas do not fit side by side.

- `AppProjectTextualPatchTests` (14, macOS; 8 added): how columns share a width between their limits, in whole points; one word per line for measuring, keeping non-breaking spaces, formulas and text styles; only attachments that shrink make a cell follow its column; in a hosted table, three figures wider than the table each shrink to a third of it, figures that fit keep their size and the table does not stretch, and text wraps to the offered width while a table offered almost nothing keeps its widest words whole; empty cells and an empty row keep their places, and a long heading after an empty first cell stays over the second column.
- `UiReadingViewTests` (23, macOS; 2 added): through `ObsidianMarkdownText` with image files in a vault, three 500-pixel images in a table end inside a 600-point note with equal columns, and 80-pixel images keep their size.

It happened in both tries before the fix and neither after it.
- iCloud Drive, which syncs the Desktop this repository is on, kept 69 older copies of source files as "Name 2.swift" when the merge replaced them, and the build failed on the duplicate declarations. They were moved out of the repository (to `~/.graphite-fix-work/icloud-conflict-copies-2026-09-25/`), and the build and tests pass again.
- Found and fixed (reported by the user): in the file list, the contents of an expanded folder were drawn centered and squeezed together instead of as rows. The merge had wrapped each row in `.equatable()`, which makes a folder's row a single view, so the list drew the folder's contents inside it. Without the wrapper (the rows still compare by their entry), files and folders three levels deep line up with their folders, and tapping one opens it and highlights its whole row.
- The iPad's own crash logs (six copied of the seven there, 23–24 Sep, all on the build installed on 23 Sep) are one crash: indexing ran out of stack parsing a note with lists nested more than about 55 deep, and because indexing runs at every launch the app crashed again on each reopen. The current code no longer hands such a note to the Markdown parser (`MarkdownNesting`, tested on a thread with the same 512 KB stack); a Release build with that change was installed on the iPad the same evening, and 45 seconds after launch it was still running with no new crash log. Whether the note that caused the crash is in the vault the iPad opens is not known, so this does not show that the crash itself is gone.

## Not implemented yet

Obsidian community plugin installation and execution are not implemented. The future target is to run existing plugin packages obtained from Obsidian's community directory, GitHub releases, or other sources without a Graphite-specific version, preserving their settings and file formats. Compatibility has not been validated. New plugin integrations and runtime implementation are deferred until the app feels premium; UI and interaction polish, Pencil quality, essential handwriting tools, and daily Obsidian workflows take priority. See `OBJECTIVE.md` for the scope and `Docs/Architecture.md` for runtime constraints.

A full comparison with Obsidian mobile, ranked for studying on an iPad, is in `Docs/Obsidian-mobile-gaps.md`. The defects it found in existing features are fixed (see above). The main remaining items:

- Bases Kanban settings (column width, hiding empty columns, cover images, column order, a new note from a column) and moving cards between folder columns: Obsidian 1.14's keys for them are not documented. Map styles (vector tiles) in `mapTiles` show Apple's map with a notice. `html()` shows no images or frames.
- Choosing a different format for an existing drawing (use Export a Copy).
- Native text selection handles, magnifier, Look Up and Translate on PDFs while annotating: a long press selects a word and dragging extends it, Graphite's own implementation. Outside annotation, PDFKit's native selection is used.
- Undo for PDF bookmark changes (toggle the bookmark again). A PDF's undo history ends when its hidden session is released or the file reopens after an external change, and is not kept across launches.
- Embeds of one PDF now coordinate: before an embed annotates, the other embeds and a PDF view showing the file are saved. The PDF view does not do the same before its own edits, so editing a PDF in its view while an embed of it has unsaved annotations can still end in a conflict.
- Filling PDF forms: form fields are shown read-only.
- Video keeps no sound while Graphite is off screen, and pauses while Graphite shares the screen with another app, which needs Apple's multitasking-camera entitlement. One fixed video quality. A player already showing an audio or video file does not reload after a conflict version replaces it.
- Hidden tabs keep their note sessions open; only hidden PDFs beyond the most recently visible one are released. Note editors are bounded (three kept hidden), sessions are not.
- Rendering SVG files made by other applications inside the reading view (they open with the system preview instead).
- Tabs: undo history survives switching tabs, moving a tab to the other side, and reading view for the three most recently hidden notes; beyond them, after a memory warning, and when a tab opens another file, the editor is rebuilt without its history (the note's text, cursor and scroll position are kept); a file is open in at most one tab, so "Open in New Tab" on a file already open shows its tab; tab history is not saved between launches; tabs stack at most two sides, left and right; no saved named workspaces. Reading view now retains its vertical offset for the open session, with the limitations recorded above.
- Opening a second vault in its own window, as Obsidian does on the desktop; one vault is open at a time.
- Bases: a date Range and durations are shown as exact parts, where Obsidian humanizes them ("a month"); `date("not a date")` and `duration("soon")` are errors, where Obsidian gives an empty value.
- Renaming or deleting a vault's folder from Graphite (do it in Files, then open the folder again).
- Per-vault Graphite preferences: which core plugins are on, the editor defaults and the Colors palette apply to every vault on the device, where Obsidian keeps core plugin choices per vault.
- 10,000 and 100,000 file measurements on hardware.
