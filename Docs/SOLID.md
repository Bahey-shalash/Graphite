# SOLID compliance tracker

Last reviewed: 2026-09-30.

The standard is [Apply SOLID without unnecessary machinery](../RULES.md#apply-solid-without-unnecessary-machinery). [OBJECTIVE.md](../OBJECTIVE.md) remains authoritative for product behavior and ordinary-file storage. This document assesses the current working tree, including uncommitted implementations. [Architecture](Architecture.md) describes ownership and dependencies, and [Coverage](Coverage.md) records behavior and executed checks.

**Overall: partially followed.** Module direction, value types, actor ownership, and several real substitution boundaries support the standard. The largest gaps are broad workspace responsibilities, direct access to shared mutable services, and interfaces that expose more capabilities than their consumers need. Full compliance is not established.

This is a focused source review of the package dependencies, storage boundary, workspace and document sessions, Bases providers, conflict-version adapters, video capture, editor retention, and Pencil/PDF shared services. It is not a line-by-line audit of every implementation. No application code changed and no build, automated tests, simulator interactions, or physical-device checks ran for this documentation update. Test references below describe existing assertions inspected in source, not new passing results. A numerical percentage would imply a coverage measure this review does not have.

## Assessment by principle

“Partial” means the reviewed code has both supporting evidence and an identified gap. “Validation incomplete” means existing tests do not establish the full contract across implementations and environments.

Concrete actors, enum switches, and framework singletons are not automatically violations. Assess whether a consumer needs the whole capability and whether a real extension or substitution is obstructed. Main-actor isolation protects shared service access from data races, but does not remove the ownership and injection gap. Immutable policy values and bounded caches should not be conflated with mutable product services.

## Contract evidence and its limits

- **Conflict versions:** [FileVersionConflictTests](../Tests/GraphiteAppleTests/FileVersionConflictTests.swift) uses real local `NSFileVersion` objects, with `.everyOtherVersion` listing because local versions are not unresolved provider conflicts. Assertions cover stale replacement, refusal to overwrite a separate destination, selective removal, missing versions, and presenter notifications. [WorkspaceConflictVersionsTests](../Tests/GraphiteUITests/WorkspaceConflictVersionsTests.swift) covers workspace behavior with a [test store](../Tests/GraphiteUITests/TestConflictVersionStore.swift), plus local production-adapter integration. Real iCloud/provider conflict production and download behavior remains outside that evidence.
- **Test-store failure parity:** production `coordinateWriting` throws when file coordination supplies no result. The test store's `replaceFile` instead calls `try outcome?.get()`, then removes the version and returns. Its `removeVersions` also omits production write coordination and its failures. These are source-level divergences, not a reproduced production data-loss bug. The test store can make those failure paths appear safer than production, which conflicts with the stated substitution rule.
- **Bases:** [CoreBasesDefinitionQueryEngineTests](../Tests/GraphiteCoreTests/CoreBasesDefinitionQueryEngineTests.swift) checks in-memory alias resolution, ambiguity, and property backlinks. [BaseIndexTests](../Tests/GraphiteIndexTests/BaseIndexTests.swift) runs evaluation with the index provider. [IndexFileOperationsFixTests](../Tests/GraphiteIndexTests/IndexFileOperationsFixTests.swift) checks that database lookup failure is reported. The protocol cannot throw, so [BaseIndexRecordProvider](../Sources/GraphiteIndex/BaseRecordQueries.swift) temporarily answers nil/empty and exposes `throwIfLookupFailed()` separately. `BaseDocumentModel` calls that check before publishing results. The current path handles the error, but generic consumers cannot enforce it through `BaseRecordProvider` alone.
- **Video:** [VideoRecordingTests](../Tests/GraphiteAppleTests/VideoRecordingTests.swift) injects [SyntheticCaptureSource](../Tests/GraphiteAppleTests/VideoRecordingTestSupport.swift) and inspects an MP4 produced by the actual writer. Assertions cover decoded frames/audio, codecs, pause timing, cancellation, interruptions, storage failures, and recovery. This is meaningful output evidence, but it does not verify `CameraCaptureSource` permissions, hardware timing, rotation, or system interruptions on an iPad.
- **Session safety:** [MarkdownSessionConcurrencyTests](../Tests/GraphiteUITests/MarkdownSessionConcurrencyTests.swift) and [CanvasSessionTests](../Tests/GraphiteUITests/CanvasSessionTests.swift) assert retained edits and conflict behavior. They support the sessions' safety contracts, but do not prove parity for every document implementation.

## Remaining work

All entries are open. Priority reflects impact on the engineering standard, not a confirmed user-facing failure. Preserve coordinated writes, recoverable work, native undo, and ordinary files during any refactor.

| Priority | Work | Completion evidence |
| --- | --- | --- |
| High | Bring conflict test-store failure handling into line with production. | Require a coordination outcome before success, model coordinated-removal failures, and exercise the same stale-write, absent-destination, missing-version, and failed-operation expectations against both adapters where feasible. Do not resolve versions on a failed operation. |
| High | Make workspace services and shared Pencil/PDF/draft dependencies explicit at composition boundaries. | Consumers receive the relevant instances or capabilities. Independent workspaces/tests can use separate services while intentional sharing, retained edits, and vault-switch cleanup remain covered. Framework APIs may stay inside adapters. |
| Medium | Extract coherent workflows from `WorkspaceModel` as those areas change. | Attachment/drawing publication, recording destination policy, and vault lifecycle have explicit ownership. Workspace coordinates them without retaining their implementation policy. Splitting extension files alone does not close this entry. |
| Medium | Narrow dependencies for navigation, discovery, and session persistence. | Read-only consumers do not receive replacement/deletion capability. Use closures, value types, or protocols only where they meet an actual isolation/substitution need. Avoid one forwarding interface per class. |
| Medium | Put Bases lookup failure reporting inside the provider/evaluation contract. | A consumer using only the declared capability can distinguish missing data from a failed lookup. Shared fixtures exercise both providers' link, alias, ambiguity, backlink, and error semantics. |
| Medium | Keep document/template/format extension points focused. | A concrete new handler, template, or format can be added without spreading dispatch/policy checks through unrelated views. Consolidate repeated dispatch when that extension need occurs, rather than introducing a speculative plugin registry. |
| Validation | Exercise real capture and provider lifecycle contracts. | Record hardware/provider, OS, operations, results, and limits in Coverage. Retain synthetic and local tests alongside real permission, interruption, camera-switch, placeholder, and conflict checks. |

Update this tracker when responsibilities, capability boundaries, dependency ownership, adapters, or their contract evidence change. Move an entry out of the open list only when its completion evidence exists. Feature completeness and test counts alone do not establish SOLID compliance.
