# Obsidian community plugins in Graphite

Graphite runs Obsidian community plugins: the same `main.js`, `manifest.json`, `styles.css` and `data.json` Obsidian uses, from the vault's `.obsidian/plugins` folder, without a Graphite version of the plugin. This file describes how, what works, what does not yet, and how each claim was checked.

Started on 2026-10-10, at the owner's request, ahead of the order `OBJECTIVE.md` had set. Universal compatibility is the goal, not the state: plugins that need Obsidian's desktop app or its CodeMirror editor are reported as such, and the gaps below are the work that remains. Since 2026-10-12 plugins also draw in notes' reading view, add to Graphite's menus, follow typing in the editor with their suggestions, and open their views in Graphite's sidebar and tabs.

## How it works

**A web view runs the plugins.** Obsidian's iPad and iPhone app is a web view (Capacitor); its plugins expect a browser's DOM and JavaScript. Graphite gives them the same: one `WKWebView` per open vault, running Graphite's own implementation of the `obsidian` module (`Sources/GraphiteUI/Resources/CommunityPluginRuntime`). WebKit runs the JavaScript in its content process, never on the app's main thread, so plugins cannot stall typing or Pencil input. Each vault has its own website data store (`WKWebsiteDataStore(forIdentifier:)`), so a plugin's `localStorage` stays with its vault. While no panel shows the web view, it waits in the window, invisible and not touchable (`CommunityPluginWebViewParking`): outside a window WebKit treats the page as hidden, slows its timers to about one a second and draws no animation frames, which stalls plugins that work on intervals.

**Plugins load as Obsidian loads them.** `main.js` is evaluated as a CommonJS module with Obsidian's `require`: `obsidian` is the runtime's module; `@codemirror/*` and `@lezer/*` are the real CodeMirror 6 and Lezer libraries, at the versions Obsidian 1.14.4 declares (vendored in `Vendor/`, see `Vendor/VERSIONS.md` and `Vendor/Licenses/`); Node.js and Electron modules (`fs`, `path`, `electron`, …) are stand-ins: plugins built for desktop and mobile require them as they load and use them only on desktop (Git, Copilot, Importer), so requiring one succeeds, and using one fails with the reason, as on Obsidian mobile. In WebKit, `main.js` is loaded as a script from a blob of its own, so error stacks name the plugin (WebKit's do not show `sourceURL`); in Node it is evaluated with a `sourceURL`. Obsidian's classes reach plugins as functions that ES5 subclasses can call (`_super.call(this, …) || this`). The plugin's class is constructed with the `App` and its manifest, and `onload` is awaited. A plugin that throws is unloaded and its error kept. `styles.css` is added to the page and removed when the plugin unloads.

**The runtime talks to Graphite in messages.** Graphite sends messages to `GraphitePluginRuntime.receive` (`callAsyncJavaScript`); the runtime posts to the `graphitePlugins` message handler, which answers each message (`WKScriptMessageHandlerWithReply`). Vault operations go to `CommunityPluginVaultBridge` (GraphiteCore); the rest to `CommunityPluginHost` (GraphiteUI).

Graphite's own messages to the runtime include, besides loading plugins and running commands: `codeBlock.render` (a code block, or with `kind: section` a part of a note offered to post-processors), `codeBlock.event` (a tap, typed text or a key on a shown copy), `codeBlock.release`, `view.attach`, `view.resize`, `view.close`, `menu.file`, `menu.editor`, `menu.choose`, `menu.dismiss`, `editor.update` (the focused note after a change, with the suggestions at the cursor when asked), `editor.chooseSuggestion` and `editor.closeSuggestions`, `notice.tap` (a tap on a plugin's notice or one of its buttons), and `protocol.open` (a `graphite://` or `obsidian://` link whose action a plugin registered, such as Advanced URI's `advanced-uri`). Every one Graphite waits on has a timeout. Each plugin's load result, failures and unsupported features also go to the unified log (subsystem `com.graphite.study`, category `CommunityPlugins`, public in Debug builds only).

The Node tests answer the same messages from a folder on disk (`Tests/CommunityPluginRuntimeTests/support/test-vault-host.js`); the two must keep the same operations, answers and failure kinds.

**Files.** Plugins write like another app would: the bridge's `VaultStore` coordinates with the runtime's own file presenter, so Graphite's workspace presenter hears of plugin writes and its usual handling applies (open notes reload, or keep unsaved edits and report the conflict; the index and sidebar refresh). Graphite's own saves and other apps' changes reach the plugins as `create`, `modify`, `delete` and `rename` events. `vault.modify` and the adapter's `write` send the revision the plugin last read; a file that changed since is refused, the plugin's promise rejects, and Graphite shows a notice. `vault.process` calls for one file run one after another, as in Obsidian, where `process` reads and writes in one step; each write expects the revision its own read returned, and a file changed by another app meanwhile is read and transformed again (three times at most). Property types (`app.metadataTypeManager.setType`) change at once and are written to `types.json` together, so a plugin setting several at load (Tasks sets 22 when they are missing) writes the file once. A note that starts with a UTF-8 byte order mark keeps it. Plugins can read and write anywhere inside the vault, hidden folders included, as in Obsidian; never outside it.

**Metadata.** `MetadataCache` reads every note once in the background (four at a time, at most 4 MB each), then again when it changes, and keeps only the metadata: headings, links, embeds, tags, frontmatter and its links, sections, list items with tasks, blocks and footnotes, with Obsidian's positions in UTF-16 code units, and the vault's `resolvedLinks` and `unresolvedLinks`, resolved as Obsidian resolves them (beside the note, then from the root, then by name or the end of a path, ignoring case). Notes iCloud or another provider keeps only in the cloud are not read, so plugins never download the vault.

**Editor.** When a command runs or the focused note changes, the runtime receives the note's text and selection. The `Editor` a plugin gets (`getValue`, `getLine`, `replaceSelection`, `replaceRange`, `transaction`, `setCursor`, `exec` for line commands, …) works on that copy; edits made together are sent back as one change once the plugin's code returns. `CommunityPluginEditorChange` (GraphiteCore) turns it into the smallest `MarkdownTextEdit`, which the note's session applies through its editor, so Undo takes it back. A command waits a moment for insertions the editor has not applied yet (a paste, a recording's link), so the plugin starts from the note as the person sees it. The change is refused, with a notice, when the note no longer has the text the plugin saw; a note in reading view cannot be edited by a plugin. Positions are lines and UTF-16 columns, which JavaScript, CodeMirror and `NSString` all count alike.

**Interface.** A plugin's modals, suggestion lists and settings tabs are drawn in the web view, which Graphite shows as the plugin panel: a sheet over the workspace, or inline on the plugin's page in Settings. Its views open in Graphite's sidebar or tabs (below). Settings tabs draw either with `display()` or, for plugins written for Obsidian 1.13, from `getSettingDefinitions()` (controls, validation, `visible` and `disabled` predicates, groups, lists and pages). Notices appear as Graphite's own toasts and menus as native dialogs. Commands appear in the command palette with Obsidian's names ("Plugin: Command"); editor commands only while a note is open for editing. Ribbon buttons and open plugin views ("Show …") are listed in the palette too. Icons are Lucide's, as in Obsidian, with Obsidian's older icon names mapped. The panel uses Obsidian's CSS variables, so plugin styles apply, in Graphite's colors and Apple's system font, light and dark.

**Settings and consent.** Settings › Community plugins has Obsidian's "Turn on community plugins" switch, per vault and per device, off until the person turns it on, with a warning that plugins run code with access to the vault and the network. Which plugins are on is `.obsidian/community-plugins.json`, written as Obsidian writes it and merged with changes Obsidian made, so Obsidian and Graphite agree. Each plugin's settings stay in its `data.json`, written as Obsidian writes it (`JSON.stringify(data, null, 2)`). A plugin whose `data.json` changes elsewhere hears of it (`onExternalSettingsChange`). Secrets (`app.secretStorage`) are kept in the device's keychain, outside the vault: the data protection keychain on iPad and iPhone, the login keychain on a Mac whose Graphite build is signed without an application identifier (the data protection keychain refuses such an app with error -34018). Each installed plugin shows its state, the modules it asks for that Graphite lacks, the unsupported features it reached while running, and its recent errors.

**Installing.** Settings › Community plugins › Browse lists Obsidian's community directory (`obsidianmd/obsidian-releases`), searchable: the plugin with the name searched for comes first, then names that start with it, names that contain it, and the rest. Installing reads the plugin's current `manifest.json` from its repository and downloads that GitHub release's `main.js`, `manifest.json` and `styles.css` into `.obsidian/plugins/<id>/`, never touching `data.json`, so an update keeps the settings. When the newest release needs a newer plugin API than Graphite provides, the newest release whose `minAppVersion` fits is chosen from the repository's `versions.json`, as Obsidian does. A plugin can also be installed from any GitHub repository (`owner/name`), and a plugin folder copied into `.obsidian/plugins` by Obsidian, Files or another app is found as it is.

**Compatibility before running.** `CommunityPluginCompatibility` reads the manifest and the code without running it: a plugin marked `isDesktopOnly`, or needing a newer API than the one Graphite provides (`1.14.4`, the version of `obsidian.d.ts` the runtime follows), is not loaded, as Obsidian mobile would not load it; the modules its code mentions that Graphite lacks are listed, since a plugin may reach them only on desktop. The CodeMirror and Lezer modules Obsidian gives plugins are not among them: the runtime provides them.

**In notes, menus, typing and tabs.** Graphite's own views are native, so a plugin cannot draw into them directly; four bridges connect them.

- *Code blocks and post-processors in the reading view.* A fenced block in a language a plugin registered (`registerMarkdownCodeBlockProcessor`, matched on the first word of the fence's info as Obsidian matches it) becomes a block of its own in the reading view. The plugin draws it in the runtime's page, in a transparent area within the page's view (so plugins that draw only what is on screen, such as Tasks, draw it) at the note's column width, and keeps it current as in Obsidian; `getSectionInfo` gives the block's lines and, for an open note, its text. Graphite shows a copy of the block's HTML in a small `WKWebView` inside the note (`CommunityPluginCodeBlockView`), with the plugins' style sheets (their `styles.css` and styles their components add to the page), the note's text size, accent, and light or dark appearance. The copy runs no script of the page (`allowsContentJavaScript` off); Graphite's own script, in its own content world, reports its height, patches it in place when it changes so a field being typed in keeps its text and caret, and turns taps, typed text and keys (Return, Escape, arrows, Tab) into element paths the runtime replays on the plugin's element: a tap as pointer, mouse and click events, typed text as the field's value with `input` and `change`. Links plugins draw open through Graphite, never in the plugins' page. While any plugin registers a Markdown post-processor, runs of Markdown are divided into Obsidian's sections (one per paragraph, list, table, quote or code block, through swift-markdown; a run with reference definitions stays whole) and each is offered to the post-processors, rendered as CommonMark HTML with internal links. A section stays Graphite's own rendering unless a post-processor changed what it shows (its text, or its pictures, controls and tables) or attached a child that keeps it current (`addChild`, as Dataview's inline queries do); only then does the plugin's version replace it, alive like a code block. A task checkbox in such a section ticks the task in the note through Graphite. A block that takes more than 20 seconds, fails, or whose plugin stops shows a message with its code; a copy over 4 MB is not shown.
- *Code blocks in Live Preview.* As in Obsidian, the same blocks are drawn by their plugin in Live Preview while the cursor is elsewhere (`LivePreviewBlock.Kind.pluginCodeBlock`, found by `LivePreviewBlockScanner` in the languages plugins registered), with the Edit Source button revealing the code. Since the block moves as the note is edited above it, `getSectionInfo` looks the block up in the note each time the plugin is given it (drawn, or tapped), and gives no lines when two blocks hold the same code, so a plugin never edits another block's lines. Post-processors do not run in Live Preview, as in Obsidian, which runs them only in the reading view.
- *Context menus, hovering and drags in copies.* The plugins' page marks each element a plugin listens on for `contextmenu`, hovering (`mouseover`, `mouseenter` and their pointer twins), presses (`mousedown`, `pointerdown`, `touchstart`) or drag and drop (`data-graphite-listens`, written as listeners are added), and copies carry the mark. A copy then forwards a right-click, or a long press of half a second on a touch screen (the plugin opens its menu, Notebook Navigator's file menu for one), the pointer moving onto and off elements (a mouse, trackpad or hovering Pencil), and a press that moves: drag and drop over the elements under the finger for an element marked `draggable` (the only elements a finger holds instead of scrolling), and with a mouse or trackpad also the presses and moves sliders follow. A tap stays a tap; a press or long press that became a menu or a drag is not also a tap.
- *Menus.* While plugins listen for `file-menu`, `files-menu`, `editor-menu` or `url-menu`, Graphite asks them for items when a menu opens (`CommunityPluginMenus.swift`), giving them two seconds. The note editor's edit menu ends with the items for the cursor, filled in as the menu opens (`UIDeferredMenuElement`); on a web address (a Markdown link's, one in angle brackets, or a bare one) it also has the items for links (`url-menu`). In the Mac app a right-click or Control-click asks for them before the context menu opens, after moving the cursor to the click as Obsidian does. Several files: the file list's options offer Pick Files for Plugins while plugins add file items, which shows a check circle beside each file; Plugin Actions… then lists the items for the files picked (`files-menu`). A file's or folder's menu in the file list, a note's More menu (`more-options`) and a tab's menu (`tab-header`) show Plugin Actions…, which lists the items in a dialog named after the file: SwiftUI's menus are built before they open and cannot wait for plugins. The chosen item's callback runs; Graphite does not wait for it, since it may open a window that waits for the person. The editor's `getClickableTokenAt` finds the tag, link or web address at the cursor, as Obsidian does for these menus.
- *Typing.* While plugins listen for `editor-change` or registered an `EditorSuggest`, each change and cursor move of the focused note sends the note to the runtime (`CommunityPluginTyping.swift`), each after the one before, so a plugin that remembers where its suggestion started (Natural Language Dates' `@`) sees every key. Plugins hear `editor-change`; the registered suggests are asked in order, and the first whose `onTrigger` answers has its items, at most its `limit`, read from what `renderSuggestion` drew (Obsidian's title and note, or the text), shown in Graphite's own suggestion list with the plugin's name. Choosing one runs `selectSuggestion`, whose edits come back as one editor change, undoable; Escape closes the plugin's suggest, and a suggest that stops answering is closed, as in Obsidian. Notes longer than 512 KB are not sent at each change, and a plugin that takes more than four seconds is skipped for that change. The Mac app's editor does the same since 2026-10-21: it sends each change and cursor move while it has keyboard focus, shows the same suggestion list at the cursor (the arrow keys move through it, Return or Tab chooses, Escape closes it), and offers pastes to plugins. Obsidian's editor state fields (`editorInfoField` and the others) exist, and `editor.cm.state.field` answers them with the note's view (Tasks needs it); anything else on `editor.cm` reports that it needs CodeMirror's editor view.
- *Views.* A view a plugin opens in one of Obsidian's sidebars (`getLeftLeaf`, `getRightLeaf`, `ensureSideLeaf`) is a panel of Graphite's sidebar, with its icon (mapped from Lucide to SF Symbols) in the sidebar's picker beside Files, Tags, Properties and Bookmarks; the picker offers three plugin views and the one shown, and the palette lists them all. A view split from the note (`splitActiveLeaf`, `getLeaf('split')`; Mind Map) opens on the other side of Graphite's split, the note staying in focus; any other view (`getLeaf('tab')`) opens in a tab named after it (`CommunityPluginViews.swift`). Its leaf is laid out in the plugins' page at the size of its tab or panel, resized with it, and shown as a copy like a code block, scrolling inside and following the system's text size. `revealLeaf` opens the sidebar on the view or brings its tab forward. Closing the tab closes the view (`detach`); a file opened in its tab replaces it; a view a plugin closes leaves its tab empty. Views are restored after a restart, as Obsidian restores its workspace: the vault's saved tab layout keeps, for each tab showing a plugin view, the view's type and the state it gives (`getState`), and the sidebar's plugin views with the one shown; once the plugins have loaded, each opens again in its tab or panel (`view.restore`), and a view no plugin shows any more leaves its tab empty.
- *Files in plugins' views, live.* A file whose extension a plugin registered (`registerExtensions`; Fountain's `.fountain`), or a note a plugin shows in a view of its own (it patches `WorkspaceLeaf.setViewState`, as Excalidraw does for notes with `excalidraw-plugin` in their frontmatter), opens in that view in a tab: Graphite asks the runtime (`file.openInView`) before opening such a file, and the runtime announces the registered extensions and whether `setViewState` is patched (`fileViews.changed`), again over the seconds after layout-ready since plugins patch it late. These views are shown live: the tab shows the runtime's own web view, where the view's leaf fills the page (`view.live`), so touches, Apple Pencil, drags, gestures and typing reach the plugin as in Obsidian, which copies cannot do. There is one web view per vault, so one view is live at a time, and switching tabs moves it, each view keeping its state in the page. Two live views on screen together (two drawings in a split) swap: the one giving up the web view leaves a picture of itself in its tab, and a tap there swaps them back. As they appear, the view on the focused side takes the web view; the other, until tapped, says it is in use and offers Show Here. The plugin panel takes the web view while it shows. The page never zooms or rubber-bands (its viewport, as Obsidian mobile's), so a pinch reaches the plugin (Excalidraw zooms its canvas). Apple Pencil reaches the page as WebKit's pen pointer events (`pointerType` "pen", `pressure`, `tiltX`, `tiltY`, hovering as moves without buttons), which Excalidraw draws with as in Obsidian on iPad, itself a WebKit view; no recognizer of Graphite's sits on the live web view. When Graphite leaves the screen, every file view saves what it holds (`views.saveFiles`, `FileView.save`), so a drawing's last strokes survive iOS ending the app.
- *Bases views from plugins.* A view type a plugin registered (`registerBasesView`; TaskNotes' Kanban, calendars and agenda) shows in Graphite's base, live, in place of the "not supported" message: Graphite sends the base's matching files by group (`basesView.open`, `basesView.update` when they change), and the runtime gives the plugin's `BasesView` entries whose values come from the vault's metadata, the view's settings from the `.base` file (`config.get`, `getOrder`, `getSort`), grouping by the view's `groupBy`, and Obsidian's `controller.query.views` and `viewName`. Formula columns come evaluated by Graphite, per file (`formulaValues`), as Graphite's own views show them. TaskNotes' calendar draws its week and month views with the vault's tasks.
- *Paste and drop.* While plugins listen for `editor-paste` or `editor-drop`, a paste into a note (its text and HTML) or a drop on it (the files' names and types) goes to them first (`editor.paste`, `editor.drop`), for at most 1.5 seconds; a plugin that calls `preventDefault()` takes it over and makes its edits through the editor (Link or Card's card, link or plain address), otherwise Graphite pastes or inserts as it does without plugins.

## What works

Checked in the Node tests (jsdom, not WebKit), and the parts listed under How it was verified in the app, in the iPad simulator:

- Loading and unloading, with everything a plugin registered removed: commands, ribbon buttons, views, setting tabs, styles, events, intervals, DOM listeners.
- `loadData` and `saveData`; the vault, its adapter (hidden files and binary data included) and `FileManager` (`processFrontMatter`, `generateMarkdownLink`, `getAvailablePathForAttachment` following the vault's attachment setting, `getNewFileParent`, `renameFile`, `trashFile`).
- The metadata cache and link resolution described above, `resolveSubpath`, `getAllTags`, `parseFrontMatter*`, `getFrontMatterInfo`.
- Commands (`callback`, `checkCallback`, `editorCallback`, `editorCheckCallback`), editor changes as one edit, the active file and `MarkdownView`, `openLinkText`.
- Modals, `SuggestModal` and `FuzzySuggestModal` with the keyboard, settings tabs with text, toggle, dropdown, slider and button controls, declarative settings with validation and `visible` predicates, menus, notices, icons.
- Code block processors and post-processors in the reading view, plugins' items in file, folder and editor menus, `editor-change` and `EditorSuggest` in the note editor, and plugin views in the sidebar and tabs, as described above.
- `requestUrl`, `moment`, `parseYaml` and `stringifyYaml`, `debounce`, fuzzy and simple search, `htmlToMarkdown`, `sanitizeHTMLToDom`, base64 and hex helpers, `Platform` (mobile, iOS, tablet or phone).

## What does not work yet

Each of these is reported to the person, per plugin, when a plugin uses it (Settings › Community plugins), or refused with the reason:

- **CodeMirror editor extensions.** The libraries load, so plugins that define extensions load, but Graphite's editor is native TextKit and the extensions do not run: Live Preview decorations and widgets, editor keymaps and autocompletion of plugins such as Outliner, Advanced Tables, Various Complements, or the editor parts of Tasks and Dataview.
- **In Live Preview**, post-processors do not run, as in Obsidian (code blocks do, above). Post-processors see each section's CommonMark HTML, not Obsidian's (no `task-list-item` classes, tags and callouts as text), so ones that look for Obsidian's markup (Tasks' rendering of task lines, Iconize's icons in notes) change nothing and Graphite's rendering stays.
- **Inside copies of blocks and views**, a finger drag reaches the plugin only on elements marked `draggable`; drags that follow plain presses (sliders, dnd-kit lists) need a mouse or trackpad. Listeners on the page's document itself rather than an element are not seen, and hover previews of links (`hover-link`) are not shown. A plugin control in a copy that needs a real user gesture in its own page may be refused by WebKit; the clipboard goes through Graphite, and file pickers in windows on the plugin panel open the system's (Importer).
- **Menus**: tag menus outside the editor, and `url-menu` outside the note editor (links in the reading view and in copies). In the file list's menus, plugins' items open in a dialog instead of the menu itself.
- **Typing**: notes over 512 KB; drops in the Mac app's editor. Drops give plugins the files' names and types, not their contents.
- **Views**: only one live view takes touches at a time (the other on screen is a picture until tapped); linked view groups. Excalidraw's embedded notes are drawn from Graphite's rendering of the note (frontmatter hidden, highlights and callouts as Obsidian's elements), not Obsidian's: math stays as text, and a plugin's block inside the note is drawn only if its plugin is on.
- **Hover previews**, pop-out windows, several selections at once (the main one is kept), `Editor.undo` and `redo` (Graphite's Undo works), setting file times on write, `FileSystemAdapter`, Obsidian's bundled MathJax, Mermaid, Prism and PDF.js loaders (PDF++ and Math Mirror need them). `vault.setConfig` writes the appearance settings Graphite shares with Obsidian (theme, snippets, fonts) through Graphite; `theme` (light or dark) and any other setting are kept for the plugins until they restart, the others reported, without failing the plugin. `getFullPath` gives the path under the vault's name, not the device's folders.
- **Desktop-only plugins** (`isDesktopOnly`) are not loaded, and code that uses Node.js or Electron fails saying so, as on Obsidian mobile.
- **Plugins that replace Obsidian's interface**: its file explorer (make.md, Reveal Folded), its tab, status and title bars (Hider), its editor toolbar (Editing Toolbar), its Quick Switcher (Accent Insensitive Search), its canvas and Maps (Advanced Canvas, Advanced Maps), and plugin views for a note (Excalidraw's drawings are notes it shows in its own view): Graphite's interface is native and does not let plugins take these over.
- **Obsidian's undocumented internals.** The most used are provided (`app.plugins`, `app.commands`, `app.internalPlugins` with the Daily notes and Templates settings, `app.setting`, `app.metadataTypeManager` over `.obsidian/types.json`, `vault.getConfig`, `metadataCache.getCachedFiles`, `getTags`, `getBacklinksForFile`, `workspace.registerHoverLinkSource`, and, hidden as on Obsidian mobile, `app.statusBar` and the settings header with its back button). Obsidian's CodeMirror editor view (`editor.cm`, apart from its state fields) and its embedded note editor (`app.embedRegistry`) report themselves as unsupported (Outliner's folding, Kanban). `app.foldManager` is a stand-in that keeps no folds (Graphite keeps them itself), and `i18next` gives Obsidian's English interface strings. Others are missing, and a plugin calling one fails with a JavaScript error that its row in Settings shows.
- **Themes and CSS snippets** style the plugins' page and the copies of blocks and views only; Graphite's notes and native interface keep their own look (theme Phase 1 is not started).
- Obsidian mobile does not show its status bar; neither does Graphite: `addStatusBarItem` adds an element to `app.statusBar`, which is not shown.

## Running the checks

```bash
cd Tests/CommunityPluginRuntimeTests
npm ci
npm test                                  # the runtime's tests
npm run build-compatibility-plugins       # clones and builds the real plugins (needs GitHub and npm), in the temporary folder by default
npm test                                  # again, now with the real plugins
npm run api-coverage -- --markdown        # Docs/Community-plugin-API-coverage.md
npm run build-vendored-libraries          # regenerates Vendor/ from the pinned versions
```

A cache folder given to `build-compatibility-plugins` must not have a hidden folder in its path (`~/.cache/…`): Rollup's TypeScript plugin then skips every source file.

`swift test` runs `CommunityPluginTests` with the other Core tests and `CommunityPluginSecretStoreTests` with the Apple tests. The integration tests on an iPad simulator (`Docs/Coverage.md`, How to run the checks) run `CommunityPluginHostTests` and the secret store's tests inside the app.
