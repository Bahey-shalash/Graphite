## 1. Summary

**What the area does.** The editor turns a Markdown note's exact source into Obsidian's Live Preview and Source mode on a TextKit 2 text view: `UITextView` on iPad and iPhone, `NSTextView` on the Mac. Characters are never changed by styling; Live Preview hides markup with attributes ([MarkdownTextStyler.swift:863-866](../../../Sources/GraphiteUI/MarkdownTextStyler.swift#L863-L866)), draws bullets, checkboxes, quote bars and inline math with a custom layout fragment ([ConcealedReplacementLayoutFragment.swift:26](../../../Sources/GraphiteUI/ConcealedReplacementLayoutFragment.swift#L26)), and places SwiftUI views over concealed blocks (tables, callouts, math, embeds, bases, properties) whose last line reserves the view's measured height ([MarkdownTextStyler.swift:868-887](../../../Sources/GraphiteUI/MarkdownTextStyler.swift#L868-L887), [LivePreviewRenderedBlocks.swift:363-405](../../../Sources/GraphiteUI/LivePreviewRenderedBlocks.swift#L363-L405)). `MarkdownSession` owns the note's text, saving, conflicts, queued insertions and per-note view state ([MarkdownSession.swift:5-462](../../../Sources/GraphiteUI/MarkdownSession.swift#L5-L462)); `MarkdownEditorRetention` keeps hidden text views so undo history survives tab switches ([MarkdownEditorRetention.swift:28-142](../../../Sources/GraphiteUI/MarkdownEditorRetention.swift#L28-L142)).

**Shape.** `NativeMarkdownEditor.swift` (3523 physical lines) contains two complete, separately written declarations of `NativeMarkdownEditor` and its `Coordinator`: iPad at [NativeMarkdownEditor.swift:551-2326](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L551-L2326), Mac at [NativeMarkdownEditor.swift:2685-3517](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L2685-L3517). Both delegate styling to the shared `MarkdownEditorStyling` ([MarkdownEditorStyling.swift:57](../../../Sources/GraphiteUI/MarkdownEditorStyling.swift#L57)), which owns `LivePreviewTextState` (edit tracking), `RevealedMarkup`, `MarkdownBlockContextCheckpoints` and `LivePreviewRenderedBlocks`. Everything else (lifetime, folding, insertions, completion, jumps, taps, Pencil, Read Aloud, keyboard, menus) lives in the two coordinators.

**Three biggest problems.**
1. The iPad coordinator is a god object (47 stored properties, 93 functions, 6 delegate conformances; section 3.1) whose ordering rules are enforced by 7 Booleans and 16 main-queue hops; it is tested only through simulator-hosted app tests, never by `swift test` (SRP-EDITOR-01, CC-EDITOR-02, CC-EDITOR-03).
2. The two platform variants drift: the Mac coordinator never serves `recordEditorPlace`, `findRequest`, `startsEditingWhenShown`, `hasPlacedCursor`, `isTyping` or `takeEditingStartLocation` (grep `startsEditingWhenShown|findRequest|hasPlacedCursor|recordEditorPlace|isTyping` over `NativeMarkdownEditor.swift`: all 11 hits are at lines 991-1699, inside the iPad `#if`). Four defects follow (BUG-EDITOR-01 to 04, LSP-EDITOR-01).
3. Knowledge is spread over parallel lists: 6 `switch`es over `LivePreviewBlock.Kind`, 7 places per formatting command, about 12 duplicated iPad/Mac function pairs, and template literals with two owners (OCP-EDITOR-01, OCP-EDITOR-02, CC-EDITOR-04).

**Three best parts.**
1. Edit tracking is a set of small pure value types with exact range semantics and unit tests: `CharacterEdit`, `TextRangeMapping`, `CharacterEditHistory`, `PendingInsertionRequests`, `UnstyledEdit`, `LivePreviewBlockShifting`, `RevealedMarkup`, `TextDifference` ([LivePreviewEditTracking.swift:6-788](../../../Sources/GraphiteUI/LivePreviewEditTracking.swift#L6-L788); `UiEditorEditTrackingTests`, `UiEditorRevealedLinesTests`).
2. One styling engine and one rendered-block engine serve both platforms through a 5-member port `MarkdownStyledTextView` ([MarkdownEditorStyling.swift:12-22](../../../Sources/GraphiteUI/MarkdownEditorStyling.swift#L12-L22)); the Mac package tests drive the shared engine in a real `NSTextView`.
3. Native undo is preserved deliberately everywhere: insertions, external changes, table cells, checkboxes and code formatting all go through the text view or register their own inverse ([NativeMarkdownEditor.swift:1325-1357](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L1325-L1357), [NativeMarkdownEditor.swift:3119-3133](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L3119-L3133)), and a minimal diff keeps cursor and history across external edits ([LivePreviewEditTracking.swift:766-787](../../../Sources/GraphiteUI/LivePreviewEditTracking.swift#L766-L787)).

**Calls that cross responsibilities (the coupling a split must preserve).**
- Edits → folds → styling: `settleTextChange` calls `rebuildBlocks` (which moves or recomputes folds from the same snapshot), then `carryFoldsAcrossEdit`, then either `restyleEverything` + `restyleBlocksAwaitingRestyle` or `restyleUnstyledEdit` ([NativeMarkdownEditor.swift:1170-1181](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L1170-L1181)).
- Delegate → folds → edits: `shouldChangeTextIn` performs a fold-aware Return, unfolds touched sections, accepts suggestions, runs smart edits and records the pre-edit fold state, in that order ([NativeMarkdownEditor.swift:1536-1576](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L1536-L1576)).
- Selection → folds → styling → formatting → suggestions: `textViewDidChangeSelection` may move the selection out of a fold (re-entering itself), then updates the session, reveals markup, schedules code formatting and updates suggestions ([NativeMarkdownEditor.swift:1692-1708](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L1692-L1708)).
- Insertions → styling → suggestions: `apply` restyles everything, publishes and updates suggestions after the insertion ([NativeMarkdownEditor.swift:1276-1281](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L1276-L1281)).
- Placement → jumps: `positionWidgets` ends by calling `keepPinnedHeadingAtTop` ([NativeMarkdownEditor.swift:1821](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L1821)); `publish` resets the placement budgets ([NativeMarkdownEditor.swift:1744-1745](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L1744-L1745)).

**Lifecycle and ordering rules it relies on.**
- Text and saved selection are set before the delegate, or the delegate records the end-of-text cursor ([NativeMarkdownEditor.swift:659-666](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L659-L666)).
- `isPerformingEdit` must be set around every edit Graphite makes through the text view, or `shouldChangeTextIn` rewrites it as typing (6 set/reset pairs: 1265-1267, 1348-1350, 1374-1376, 1412-1414, 2161-2163; set by reading).
- `isApplyingInsertion` suppresses `textViewDidChange` and most of `textViewDidChangeSelection` until the insertion settles itself ([NativeMarkdownEditor.swift:1262-1275](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L1262-L1275), [NativeMarkdownEditor.swift:1580](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L1580), [NativeMarkdownEditor.swift:1701](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L1701)).
- Styling waits while marked text exists; block tracking does not ([NativeMarkdownEditor.swift:1167-1172](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L1167-L1172)).
- Markup is revealed on the next run-loop turn after editing begins, because UIKit places the tap's cursor after `textViewDidBeginEditing` ([NativeMarkdownEditor.swift:1590-1598](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L1590-L1598)).
- Folds move with an edit only when they were found in the snapshot the edit started from ([NativeMarkdownEditor.swift:1138-1152](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L1138-L1152)); `lengthBeforeEdit`/`editLocationBeforeEdit`/`foldedRegionsBeforeEdit` are recorded only outside a composition ([NativeMarkdownEditor.swift:1570-1574](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L1570-L1574)) and reset on use ([NativeMarkdownEditor.swift:1944-1945](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L1944-L1945)).
- On dismantle the keyboard is given up first, with `refusesFocus` set, then the text view moves to the newest remaining container, else suspends, else moves to a container made during suspension ([NativeMarkdownEditor.swift:953-976](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L953-L976)).
- A jump runs only with a window and a width, from the next run-loop turn after a layout pass ([NativeMarkdownEditor.swift:2196-2217](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L2196-L2217)).
- Placement retries are bounded: 6 quick passes, then 3 delayed tries at 0.25 s, reset by every publish ([NativeMarkdownEditor.swift:1808-1820](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L1808-L1820)).

## 4. Findings by principle

### S

#### SRP-EDITOR-01 The iPad editor coordinator owns sixteen kinds of work and 47 stored properties
- **Severity:** High
- **Evidence:** [NativeMarkdownEditor.swift:771-2325](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L771-L2325); responsibility table in 3.1 (47 stored properties and 93 functions counted by reading; 5 protocol conformances at [NativeMarkdownEditor.swift:772-773](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L772-L773)). The type is declared inside `#if canImport(UIKit)` ([NativeMarkdownEditor.swift:5](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L5)), so `swift test` on macOS never compiles it; its only tests are the simulator-hosted classes in `App/Tests` (`EditingContinuityTests`, `LivePreviewRevealTests`, `LivePreviewBlockPlacementTests`).
- **Why it matters:** NativeMarkdownEditor.swift is the most-changed file (41 of 242 commits). Every change to folding, placement, suggestions or jumps edits the same object whose ordering depends on shared flags (CC-EDITOR-03); folding and placement rules that are pure arithmetic cannot be unit-tested without a simulator.
- **Fix direction:** Keep the coordinator as the delegate adapter and move each row of the 3.1 table into an owned collaborator with its own state; pure ones (`NoteFoldingState`, `RenderedBlockPlacementScheduler` budgets, `EditorTapTargets`) compile on both platforms and get package tests. The rule "more than ~15 stored properties needs a recorded reason" fits: the adapter ends with about 6.

#### SRP-EDITOR-02 `MarkdownSession` mixes persistence, edit queue, view state, folds and UI requests
- **Severity:** Medium
- **Evidence:** 34 stored properties in 8 groups (3.5). Five callback slots are filled by other objects and must be kept consistent by them: `textDidChange` ([MarkdownSession.swift:18](../../../Sources/GraphiteUI/MarkdownSession.swift#L18)), `recordEditorPlace` ([MarkdownSession.swift:65](../../../Sources/GraphiteUI/MarkdownSession.swift#L65)), `didChangeFolds` ([MarkdownSession.swift:271](../../../Sources/GraphiteUI/MarkdownSession.swift#L271)), `willReplaceSavedText` ([MarkdownSession.swift:316](../../../Sources/GraphiteUI/MarkdownSession.swift#L316)), `applyPendingInsertionsBeforeSaving` ([MarkdownSession.swift:320](../../../Sources/GraphiteUI/MarkdownSession.swift#L320)). UI requests travel as mutable fields the editor polls: `startsEditingWhenShown`, `findRequest`, `hasPlacedCursor`, `isTyping` ([MarkdownSession.swift:97-109](../../../Sources/GraphiteUI/MarkdownSession.swift#L97-L109)).
- **Why it matters:** A request stored as a field has no owner that must answer it; the Mac editor answers none of them (LSP-EDITOR-01, BUG-EDITOR-02, BUG-EDITOR-03) and nothing fails.
- **Fix direction:** Split as in 3.5. Editor requests become one `NoteEditorRequest` enum queue with an intent method per request; each editor variant must drain it (checked by a shared contract test).

#### SRP-EDITOR-03 The iPad text view runs the paste and drop import pipeline
- **Severity:** Medium
- **Evidence:** [NativeMarkdownEditor.swift:324-519](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L324-L519): pasteboard classification, HTML-to-Markdown conversion on a detached task (415-429), PNG encoding (432-442), JPEG re-encoding at quality 0.9 (500), file reads (509), plugin offers (382-401, 462-473), and attachment stems from `WorkspaceModel.pastedImageStem()` (364, 366, 496, 504). The Mac performs the same decisions in a separate enum with different rules ([NativeMarkdownEditor.swift:2601-2658](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L2601-L2658)).
- **Why it matters:** The import rules are untestable without UIKit pasteboards and already differ by platform (LSP-EDITOR-05).
- **Fix direction:** A `PastedContentClassifier` (pure: available types and flags in, `PastedContent` enum out) and a `PastedContentImporter` (loading and encoding) shared by both text views; the text views forward `paste` and `performDragOperation` to it.

#### SRP-EDITOR-04 Two delegate callbacks each perform five or six jobs
- **Severity:** Medium
- **Evidence:** `textView(_:shouldChangeTextIn:replacementText:)` ([NativeMarkdownEditor.swift:1536-1576](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L1536-L1576)): Return after a fold, unfold on edit, accept a suggestion, smart edit, record pre-edit fold state. `textViewDidChangeSelection` ([NativeMarkdownEditor.swift:1692-1708](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L1692-L1708)): move the selection out of folds (re-entrant), record `lastSelectionLocation`, mark `hasPlacedCursor`, publish the selection, reveal markup, schedule code formatting, update suggestions. - **Why it matters:** The order inside these methods is behaviour (a suggestion must be accepted before a smart edit continues a list; folds must be recorded after both are refused), but it is expressed only as statement order inside one function.
- **Fix direction:** `shouldChangeTextIn` asks an `EditInterception` policy for a decision value (`.allow`, `.replace(MarkdownTextEdit)`, `.acceptSuggestion`, `.unfold([String])`) and then performs it; the selection callback calls one `selectionDidChange` per collaborator in a documented order.

#### BUG-EDITOR-01 On the Mac, the place remembered for a note on screen is stale, so a reopened note does not return to where it was read
- **Trigger:** On the Mac, open a note, scroll down, then close its tab (or switch vault, or let Graphite become inactive); reopen the note.
- **Path:** `removeTabDocuments` remembers places before unloading ([WorkspaceTabs.swift:211](../../../Sources/GraphiteUI/WorkspaceTabs.swift#L211), unload at [WorkspaceTabs.swift:215](../../../Sources/GraphiteUI/WorkspaceTabs.swift#L215)) → `placeToRemember(of:)` ([WorkspacePlaces.swift:42-43](../../../Sources/GraphiteUI/WorkspacePlaces.swift#L42-L43)) → `MarkdownSession.placeToRemember` calls `recordEditorPlace?()` and then reads `savedScrollLocation` ([MarkdownSession.swift:69-80](../../../Sources/GraphiteUI/MarkdownSession.swift#L69-L80)) → only the iPad coordinator ever sets `recordEditorPlace` ([NativeMarkdownEditor.swift:1014-1019](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L1014-L1019); grep `recordEditorPlace` finds no Mac assignment) → on the Mac `savedScrollLocation` is written only when the editor is suspended ([NativeMarkdownEditor.swift:2962](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L2962)), which happens after the view is dismantled, i.e. after the place was already stored → the stored place is the one the note was opened at (or the top). - **Confidence:** Traced for closing a tab; partly traced for app deactivation (whether macOS reports `scenePhase` leaving `.active` on quit was not settled by reading).

## 7. Blueprint for this area

### Target shape

### Ordered steps (each leaves the app building and behaving the same, except where a step fixes a listed bug)

### Rule feedback recorded in findings

- Function length: exhaustive one-case-per-value mapping switches (`MarkdownTextStyler.apply(_ style:)`) should be exempt from the 40-line review trigger (CC-EDITOR-01).
- Timing: UIKit and SwiftUI require "after the current update" hops to avoid re-entrancy; the rule should allow them only through one owned scheduler primitive (CC-EDITOR-02).
- Getters: private memoization caches written by getters are harmless; the rule should forbid getters that change ownership or observable state, and allow memoization explicitly (CC-EDITOR-08).
- Stored-property limit: a UIKit delegate adapter can meet "≤ 15 stored properties" once collaborators own their state; the limit is the right pressure here (SRP-EDITOR-01).
