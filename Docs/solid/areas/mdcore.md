## 1. Summary

**What the area does.** It is the Markdown brain of the app, pure Foundation code with two library parsers (swift-markdown, Yams) and one `Synchronization` import:

- *Indexing semantics*: `MarkdownSemantics.parse` turns a note into links, headings, tags, aliases and frontmatter, mapping swift-markdown positions to exact UTF-16 ranges so renames can rewrite links in place ([MarkdownSemantics.swift:39-169](../../../Sources/GraphiteCore/MarkdownSemantics.swift#L39-L169)).
- *Editor styling*: `MarkdownStyleScanner` styles visible lines per keystroke with a chunked block-state walk and caller-held checkpoints ([MarkdownStyleScanner.swift:122-188](../../../Sources/GraphiteCore/MarkdownStyleScanner.swift#L122-L188)).
- *Block finders*: reading-view blocks (`NotePreviewDocument`), Live Preview blocks (`LivePreviewBlockScanner`), block references (`NoteBlocks`), fold regions (`NoteFolding`), footnotes (`Footnotes`), color sections (`TextColorMarkup`).
- *Commands*: line and inline editing commands returning one `MarkdownTextEdit` (`MarkdownEditing`), table cell edits that change only the touched characters (`MarkdownTableEditing`).
- *Conversion*: reading-view rewriting to private-use markers (`ObsidianInlineMarkup`), LaTeX rewriting for the native typesetter (`LaTeXCompatibility`), pasted HTML to Markdown (`HTMLToMarkdown`), lexical code highlighting and formatting for 26 languages (`CodeLineHighlighter`, `CodeFormatter`).
- *Safety bounds*: `MarkdownNesting` and `YAMLNesting` refuse input deep enough to exhaust a 512 KB stack ([ParserNestingLimits.swift:3-24](../../../Sources/GraphiteCore/ParserNestingLimits.swift#L3-L24)).

RULES.md asks to "Reuse a Markdown parser rather than writing one" ([RULES.md:48](../../../RULES.md#L48)). swift-markdown is used at two sites in this area ([MarkdownSemantics.swift:66](../../../Sources/GraphiteCore/MarkdownSemantics.swift#L66), [NotePreviewDocument.swift:794](../../../Sources/GraphiteCore/NotePreviewDocument.swift#L794)); every other consumer runs its own line scanner. The scanners exist for real reasons (per-keystroke cost, exact UTF-16 ranges, Obsidian's dialect), but they do not share their line rules.

**Three biggest problems.**
1. **One Markdown, many dialects.** The same line is classified by independent code in each consumer: 7 fence trackers, 5 display-math rules, 5 ATX heading rules plus swift-markdown's headings, 7 list-marker readers, 5 thematic-break patterns, 4 code-span implementations (section 4, LSP-MDCORE-01). They disagree in reachable cases: Return inside a fenced code block in a callout inserts list markup or ends the callout (BUG-MDCORE-02), an indented ```` ``` ```` opens a fence in three views but not in the index (BUG-MDCORE-03), setext headings are headings for the index and the editor but not for the outline, anchors and section embeds (BUG-MDCORE-04).
2. **Parser bounds are not uniform.** `MarkdownNesting` guards swift-markdown in indexing ([MarkdownSemantics.swift:66](../../../Sources/GraphiteCore/MarkdownSemantics.swift#L66)) and in the reading parser ([MarkdownPreview.swift:1830](../../../Sources/GraphiteUI/MarkdownPreview.swift#L1830)), but `NotePreviewDocument.sections` parses without the guard and runs first, so a deeply nested note crashes the reading view whenever a community plugin with post-processors is on (BUG-MDCORE-01). `LaTeXCompatibility.rewritingAlignments` recurses once per nested alignment environment with no limit (BUG-MDCORE-05).
3. **Grab-bag types.** `ObsidianInlineMarkup` (330 code lines) owns the marker vocabulary, comments, block identifiers, tasks, highlights, colors, table math, math protection and equation numbers; `HTMLToMarkdown.Converter` keeps 18 stored properties, 4 of them line-position flags written at 28 sites; `TextColorMarkup` carries 165 lines of its own block parser; `MarkdownEditing` is the de facto owner of line syntax used by three block finders (SRP-MDCORE-01 to -05).

**Three best parts.**
1. **`MarkdownTable` / `MarkdownTableEditing`**: one UTF-16 layout, every edit a list of non-overlapping replacements over the original source, applied once ([MarkdownTable.swift:434-535](../../../Sources/GraphiteCore/MarkdownTable.swift#L434-L535)); spacing, pipes, indentation and line endings outside the touched cell survive; 51 tests pin exact output.
2. **Bounded, linear parsing where it was measured**: `MarkdownSourceLocationConverter` replays inline positions once per paragraph with a moving UTF-8/UTF-16 cursor ([MarkdownSemantics.swift:309-548](../../../Sources/GraphiteCore/MarkdownSemantics.swift#L309-L548)); `SortedRangeSet` turns overlap tests into binary search ([MarkdownSemantics.swift:550-579](../../../Sources/GraphiteCore/MarkdownSemantics.swift#L550-L579)); `BoundedYAML` defeats alias bombs ([MarkdownSemantics.swift:581-622](../../../Sources/GraphiteCore/MarkdownSemantics.swift#L581-L622)); `HTMLToMarkdown` caps nesting and avoids quadratic `>` scans ([HTMLToMarkdown.swift:55-60](../../../Sources/GraphiteCore/HTMLToMarkdown.swift#L55-L60), [HTMLToMarkdown.swift:149-183](../../../Sources/GraphiteCore/HTMLToMarkdown.swift#L149-L183)).
3. **Edit-as-value commands**: every editing helper returns `MarkdownTextEdit` (range in the old text, replacement, selection in the new text) ([MarkdownEditing.swift:3-14](../../../Sources/GraphiteCore/MarkdownEditing.swift#L3-L14)), so the editor applies one undoable replacement and the rules are unit-testable without UIKit; the same shape is used by `NoteBlocks.addingIdentifier`, `NoteFolding.newLineAfterFoldedSection` and `TextColorMarkup.removingColor`.

- `InlineDelimiterStack` — `inlineElements`, `lastClosedDelimiter`, open/close/write-pending.
- `HTMLToMarkdown.Converter` keeps `handleTag` as a dispatcher over `HTMLTag` plus the `pre`, inline-code and table collectors.

**Couplings and rules:**

- The Markdown scanner reuses `.string(ruleIndex: 0)` for "inside a fence" although `CodeLanguage.markdown` has no string rules ([CodeSyntaxHighlighting.swift:894-902](../../../Sources/GraphiteCore/CodeSyntaxHighlighting.swift#L894-L902), [CodeLanguages.swift:496](../../../Sources/GraphiteCore/CodeLanguages.swift#L496)); `continueOpenConstruct` is never called for Markdown, which is what keeps that safe.

**Verdict:** the descriptor-plus-feature-flags design is sound and keeps a new language to data. The scanner is large because three grammars share one struct. Proposed split: `GeneralCodeScanner` (identifiers, comments, strings, numbers, sigils, YAML keys), `MarkdownCodeScanner`, `MarkupCodeScanner`, each over a shared `CodeLineCursor` (units, state, `emit`, `matches`, `nextVisibleUnit`). `scanSigil` splits by sigil into `scanHashSigil`, `scanAtSigil`, `scanDollarSigil`, `scanDotSigil`, `scanYAMLSigil`.

- **Evidence:** the 9-digit list cap is `maximumOrderedListNumber` in [HTMLToMarkdown.swift:101-102](../../../Sources/GraphiteCore/HTMLToMarkdown.swift#L101-L102) but a literal `999_999_999` in [MarkdownEditing.swift:173](../../../Sources/GraphiteCore/MarkdownEditing.swift#L173), `(1...9)` in [MarkdownSemantics.swift:810](../../../Sources/GraphiteCore/MarkdownSemantics.swift#L810) and [NoteFolding.swift:125](../../../Sources/GraphiteCore/NoteFolding.swift#L125), and `{1,9}` in 4 regexes ([MarkdownStyleScanner.swift:621-624](../../../Sources/GraphiteCore/MarkdownStyleScanner.swift#L621-L624), [MarkdownEditing.swift:87](../../../Sources/GraphiteCore/MarkdownEditing.swift#L87)); a 12-unit scan cap appears three times unnamed ([CodeSyntaxHighlighting.swift:621](../../../Sources/GraphiteCore/CodeSyntaxHighlighting.swift#L621), [L1022](../../../Sources/GraphiteCore/CodeSyntaxHighlighting.swift#L1022), [HTMLToMarkdown.swift:763](../../../Sources/GraphiteCore/HTMLToMarkdown.swift#L763)); the CommonMark 4-column indented-code threshold is named in `NoteBlocks` ([NoteBlocks.swift:33](../../../Sources/GraphiteCore/NoteBlocks.swift#L33)) and literal in `TextColorMarkup` ([TextColorMarkup.swift:418](../../../Sources/GraphiteCore/TextColorMarkup.swift#L418), [L440](../../../Sources/GraphiteCore/TextColorMarkup.swift#L440)).
- **Why it matters:** the same CommonMark limit can be changed in one place and not the others.
- **Fix direction:** CommonMark constants (`maximumOrderedMarkerDigits`, `indentedCodeColumns`, `maximumFenceIndentation`) live once with the line syntax.

#### CC-MDCORE-08 Converted HTML is always LF and is inserted unchanged into CRLF notes
- **Severity:** Low
- **Evidence:** `finishedText` normalises to `\n` ([HTMLToMarkdown.swift:797-799](../../../Sources/GraphiteCore/HTMLToMarkdown.swift#L797-L799)); the editor inserts the result as is ([NativeMarkdownEditor.swift:418-427](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L418-L427)); `MarkdownBlockInsertion` already adapts inserted blocks to the note's line ending ([MarkdownSemantics.swift:1012-1014](../../../Sources/GraphiteCore/MarkdownSemantics.swift#L1012-L1014)).
- **Why it matters:** a paste into a Windows-ending note produces mixed line endings, against "preserve … line endings" ([RULES.md:54](../../../RULES.md#L54)). Plain-text paste does the same, so this is an editor-wide policy gap rather than an HTML defect.
- **Fix direction:** one "text inserted into a note takes the note's line ending" step at the editor boundary, reusing `MarkdownBlockInsertion`'s line-ending rule.

#### CC-MDCORE-09 Parser bounds are decided per call site instead of at the parser boundary
- **Severity:** Medium
- **Evidence:** swift-markdown is called at 5 sites in Core (grep `Document\(parsing`): guarded at [MarkdownSemantics.swift:66](../../../Sources/GraphiteCore/MarkdownSemantics.swift#L66) and by callers in ReadAloud ([ReadAloudSection.swift:15](../../../Sources/GraphiteCore/ReadAloudSection.swift#L15), [ReadAloudDocument.swift:303](../../../Sources/GraphiteCore/ReadAloudDocument.swift#L303)), unguarded at [NotePreviewDocument.swift:794](../../../Sources/GraphiteCore/NotePreviewDocument.swift#L794); the UI adds its own guard ([MarkdownPreview.swift:1830](../../../Sources/GraphiteUI/MarkdownPreview.swift#L1830)). Recursive rewriters carry individual limits (callouts 16, [NotePreviewDocument.swift:36-40](../../../Sources/GraphiteCore/NotePreviewDocument.swift#L36-L40); HTML 64, [HTMLToMarkdown.swift:55-60](../../../Sources/GraphiteCore/HTMLToMarkdown.swift#L55-L60)) and one has none ([LaTeXCompatibility.swift:259-277](../../../Sources/GraphiteCore/LaTeXCompatibility.swift#L259-L277)).
- **Why it matters:** every new parse site has to remember the guard; two sites forgot (BUG-MDCORE-01, BUG-MDCORE-05), and both fail on input a synced vault can contain.
- **Fix direction:** one `BoundedMarkdownParser.document(parsing:) -> Document?` that applies `MarkdownNesting` and is the only place `Document(parsing:)` appears; every recursive rewriter takes a depth parameter with a named maximum.

## 5. Defects and latent bugs

#### BUG-MDCORE-01 The reading view crashes on a deeply nested note while a community plugin with Markdown post-processors runs
- **Trigger:** the user (or a synced vault) has a note with quotes or lists nested past swift-markdown's stack limit in a Markdown run of two or more lines without reference definitions, and opens it in reading view while a community plugin that registers Markdown post-processors is enabled.
- **Path:** the pane enables section division when plugins post-process ([MarkdownPane.swift:207](../../../Sources/GraphiteUI/MarkdownPane.swift#L207)) → `ReadingViewBuilder` splits the body and calls `sectioned` before rendering ([MarkdownPreview.swift:294-295](../../../Sources/GraphiteUI/MarkdownPreview.swift#L294-L295)) → `dividedIntoSections` ([MarkdownPreview.swift:365-366](../../../Sources/GraphiteUI/MarkdownPreview.swift#L365-L366), [NotePreviewDocument.swift:773-777](../../../Sources/GraphiteCore/NotePreviewDocument.swift#L773-L777)) → `sections(of:)` calls `Document(parsing: markdown)` with no `MarkdownNesting` check ([NotePreviewDocument.swift:788-794](../../../Sources/GraphiteCore/NotePreviewDocument.swift#L788-L794)). The nesting guard in `ObsidianMarkdownParser` ([MarkdownPreview.swift:1830](../../../Sources/GraphiteUI/MarkdownPreview.swift#L1830)) runs only later, inside `render`. swift-markdown converts its tree recursively and crashes at 55 nested lists or 64 nested quotes on a 512 KB stack ([ParserNestingLimits.swift:3-8](../../../Sources/GraphiteCore/ParserNestingLimits.swift#L3-L8)).
- **Effect:** the app terminates. Because the last document reopens at launch ([ParserNestingLimits.swift:4-6](../../../Sources/GraphiteCore/ParserNestingLimits.swift#L4-L6)), the crash repeats on every launch while the plugin stays enabled.
- **Platforms / reach:** iPad, iPhone, Mac; only while a post-processing community plugin is on (normal path for those users).
- **Confidence:** Traced to the unguarded parse; the crash depth is the project's own measurement quoted in `ParserNestingLimits`, not re-measured here.

#### BUG-MDCORE-02 Return inside a fenced code block in a quote or callout adds list markup or ends the callout
- **Trigger:** with smart lists on, inside a code fence written in a callout (`> ```` ` … `> ```` `), the user presses Return at the end of a line such as `> - item` (common in Markdown or YAML samples), or on an empty `> ` code line.
- **Path:** Return calls `MarkdownEditing.continuingList` ([NativeMarkdownEditor.swift:1393-1394](../../../Sources/GraphiteUI/NativeMarkdownEditor.swift#L1393-L1394)) → `listLine` reads the quote prefix and marker ([MarkdownEditing.swift:87](../../../Sources/GraphiteCore/MarkdownEditing.swift#L87), [L92-L113](../../../Sources/GraphiteCore/MarkdownEditing.swift#L92-L113)) → `isInCodeOrFrontmatter` skips every line whose first non-blank character is not a backtick or tilde, so the `> ```` ` line never opens the tracker's fence ([MarkdownEditing.swift:216-218](../../../Sources/GraphiteCore/MarkdownEditing.swift#L216-L218)) and returns false ([L220](../../../Sources/GraphiteCore/MarkdownEditing.swift#L220)) → for `> - item` the continuation `\n> - ` is inserted ([MarkdownEditing.swift:174-180](../../../Sources/GraphiteCore/MarkdownEditing.swift#L174-L180)); for an empty `> ` line the quote marker is replaced by nothing ([MarkdownEditing.swift:167-169](../../../Sources/GraphiteCore/MarkdownEditing.swift#L167-L169)). - **Effect:** code text gains list markers the user has to delete; or the `>` of the current line disappears, which ends the callout and its code block at that line.
- **Platforms / reach:** iPad and iPhone (the UIKit editor; grep `continuingList\(` over `Sources/**` finds no Mac caller); normal typing path.
- **Confidence:** Traced.

#### BUG-MDCORE-03 A fence line indented four or more columns opens a code block in the editor, the reading view's blocks and Live Preview, but not in the index
- **Trigger:** a line of four or more spaces followed by ```` ``` ```` — inside an indented code block that shows Markdown, or as a lazy continuation of a paragraph — with no matching fence before the next headings, tables or callouts.
- **Path:** editor: the chunked walk treats indentation as transparent ([MarkdownStyleScanner.swift:287-289](../../../Sources/GraphiteCore/MarkdownStyleScanner.swift#L287-L289)) and `nextState` tests the trimmed content ([MarkdownStyleScanner.swift:323-326](../../../Sources/GraphiteCore/MarkdownStyleScanner.swift#L323-L326), trimming at [L369](../../../Sources/GraphiteCore/MarkdownStyleScanner.swift#L369)), so following lines get `.codeBlock` spans ([L434-L438](../../../Sources/GraphiteCore/MarkdownStyleScanner.swift#L434-L438)). Live Preview: the scanner skips to the closing fence ([LivePreviewBlocks.swift:60-82](../../../Sources/GraphiteCore/LivePreviewBlocks.swift#L60-L82)). - **Effect:** the rest of the note (to the next fence line) is styled as code in Live Preview and Source mode; the reading view draws its headings without anchors (links to them do not scroll) and its callouts, embeds and display math as plain Markdown; Live Preview renders no tables, math or callouts there.
- **Platforms / reach:** iPad, iPhone, Mac; edge-case input on the normal path.
- **Confidence:** Traced inside Graphite; CommonMark's rule is the one `MarkdownCodeRanges` states ([MarkdownSemantics.swift:692-694](../../../Sources/GraphiteCore/MarkdownSemantics.swift#L692-L694)).

#### BUG-MDCORE-04 Setext headings are headings for the index and the editor but missing from the outline, heading anchors, section embeds and folding

#### BUG-MDCORE-05 Nested alignment environments recurse without a limit while a formula is prepared for display
- **Trigger:** a formula containing many nested `\begin{aligned}…\end{aligned}` (generated or crafted LaTeX in a synced note), shown in reading view or a Live Preview math, table or callout view.

- **Confidence:** Partly traced. The unbounded recursion and the per-level rescans are read; the depth at which the stack runs out is not measured.
