# Invariants: the acceptance specification

Snapshot: b13dec3 (main, 2026-10-18).

This is what the cleanup must never break: every behaviour and every piece of data users depend on, one rule per row. The characterization tests of Phase 0 pin these rows before any code moves. A row is satisfied when the production path (not a copy of it) passes its test idea.

## How to read this document

- **IDs are permanent.** A row keeps its ID for the life of the project. IDs are never renumbered and never reused. A retired row is struck through (`~~D-07~~`) and its Rule cell says why it retired; new rows take the next free number of their prefix.
- **(defect)** at the start of a Rule marks current behaviour that the cleanup must *not* carry over. Each links its `BUG-*` in [defects.md](defects.md). The Test idea of a (defect) row is the regression test of the corrected behaviour; no characterization test may pin the defective behaviour. When a defect is fixed, the row is struck through and the corrected rule lives in the neighbouring row that already states it.
- **Rule** is one present-tense sentence with exact key strings, formats and numbers. Every format, key, name and number comes from an area blueprint or from a code search of the snapshot; every link was checked by script for file and line range, and one in five was read by hand against the rule it supports.
- **Enforced today** links the line that makes the rule true. Links are relative to this file.
- **Test idea** starts with **No test today.** when no existing test pins the rule; Phase 0 writes those first (the list is at the end). "Golden file" means a committed fixture compared byte for byte; a golden fixture written by b13dec3 is the oracle, never a fixture produced by the new code.
- **Source** lists the area invariant IDs (`<AREA>-INV-NN`, in the Blueprint section of the area document) and finding or bug IDs the row merges. One rule is one row; where several areas stated it, all their IDs are listed.
