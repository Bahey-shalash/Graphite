## 1. Summary

**What the area is.** Graphite is a Swift package with six library/executable targets (`GraphiteCore`, `GraphiteIndex`, `GraphiteApple`, `GraphiteVoices`, `GraphiteUI`, `GraphiteBenchmarks`) and a thin Xcode app target whose only source file is `App/GraphiteApp.swift` ([project.pbxproj:305-312](../../../Graphite.xcodeproj/project.pbxproj#L305-L312)). The dependency direction is clean at module level — Core imports only Foundation, CoreGraphics, Yams, Markdown, CryptoKit, zlib and Synchronization; Index and Apple depend only on Core; Voices on Core and Apple; UI on everything ([Package.swift:24-38](../../../Package.swift#L24-L38)). Below that line the shape is one application object: `WorkspaceModel` is constructed inside a SwiftUI `@State` initializer ([GraphiteRootView.swift:8](../../../Sources/GraphiteUI/GraphiteRootView.swift#L8), [GraphiteMacScenes.swift:12](../../../Sources/GraphiteUI/GraphiteMacScenes.swift#L12)), builds its own services ([WorkspaceModel.swift:15](../../../Sources/GraphiteUI/WorkspaceModel.swift#L15), [:178-209](../../../Sources/GraphiteUI/WorkspaceModel.swift#L178-L209)), and is handed whole to 74 view and model declarations.

**The three biggest problems.**
1. **No composition root and an application-wide aggregate.** `WorkspaceModel` owns vault lifecycle, tabs, search and indexing, file management, drawings, recording, Read Aloud wiring, plugins, themes, conflict versions and 13 presentation flags (86 stored properties, part 3). Collaborators are created in property initializers and singletons, so no test or second scene can substitute any of them (DIP-ARCH-01, SRP-ARCH-01, ISP-ARCH-01).
2. **Persisted device state has no owner.** About 91 `UserDefaults` key names are declared in about 25 files under four naming schemes, read through three access paths (instance property, static reader, `@AppStorage` with its own default), and in two places used as a message bus between commands and views (DIP-ARCH-03, DIP-ARCH-04). Removing a vault forgets only some of its keys (BUG-ARCH-06).
3. **Rules implemented more than once disagree.** Media classification has two vocabularies, so following a link to a missing `.flac` creates `name.flac.md` (BUG-ARCH-01); link resolution exists in four implementations with different folder and ambiguity rules (BUG-ARCH-05); URL-to-vault-path mapping is written seven times (CC-ARCH-08). Save failures are swallowed at the two moments that matter most — quitting on the Mac and switching vaults (BUG-ARCH-02, BUG-ARCH-04).

**The three best parts.**
1. **Module direction and a platform-free Core.** No file in `GraphiteCore` imports UIKit, AppKit, SwiftUI, PDFKit, PencilKit, AVFoundation or WebKit (import grep, part 2), so every Obsidian-format parser and policy is testable on any platform.
2. **Concurrency escapes are documented.** Every one of the 20 `@unchecked Sendable` conformances carries a comment stating the invariant it relies on (part 4, Clean code), Swift 6 language mode is on for the package (`swift-tools-version: 6.0`, [Package.swift:1](../../../Package.swift#L1)) and the app (`SWIFT_VERSION = 6.0`, [project.pbxproj:383](../../../Graphite.xcodeproj/project.pbxproj#L383)), and long-lived background work has owners with run identifiers (`indexingRunIdentifier`, [WorkspaceModel.swift:199-201](../../../Sources/GraphiteUI/WorkspaceModel.swift#L199-L201), [:526-547](../../../Sources/GraphiteUI/WorkspaceModel.swift#L526-L547)).
3. **Stored formats degrade without destroying data.** `VaultLibrary` keeps vault entries it cannot decode and writes them back unchanged ([VaultLibrary.swift:69-109](../../../Sources/GraphiteUI/VaultLibrary.swift#L69-L109)); the index is a migrated, disposable cache with named migrations ([VaultIndex.swift:80-187](../../../Sources/GraphiteIndex/VaultIndex.swift#L80-L187)); the drawing-draft store serializes its writes so a removal cannot be overtaken ([DrawingEditorDraftStore.swift:132-138](../../../Sources/GraphiteUI/DrawingEditorDraftStore.swift#L132-L138)).

Whether SwiftUI re-creates `GraphiteMacScenes` during a run was not settled by reading; the dependency on it is the defect in design.

**Process-wide state.** The design relies on exactly one workspace per process: iPadOS is held to one scene ([Info.plist:38-42](../../../App/Info.plist#L38-L42), comment at [GraphiteApp.swift:21](../../../App/GraphiteApp.swift#L21)) and the Mac to one `Window` ([GraphiteMacScenes.swift:22-30](../../../Sources/GraphiteUI/GraphiteMacScenes.swift#L22-L30)). ## 4. Findings by principle

### S

#### SRP-ARCH-01 `WorkspaceModel` is an application-wide aggregate of 86 stored properties and a dozen responsibilities
- **Severity:** High
- **Evidence:** 86 stored properties counted by reading [WorkspaceModel.swift:12-209](../../../Sources/GraphiteUI/WorkspaceModel.swift#L12-L209), [:1011](../../../Sources/GraphiteUI/WorkspaceModel.swift#L1011), [:1097-1105](../../../Sources/GraphiteUI/WorkspaceModel.swift#L1097-L1105), [:1277](../../../Sources/GraphiteUI/WorkspaceModel.swift#L1277); 24 `extension WorkspaceModel` declarations in 23 further files (grep `extension WorkspaceModel`), from `WorkspaceTabs.swift:84` to `CommunityPluginViews.swift:192` and `LassoTools.swift:72`/`:85`; the responsibility table in part 3.3 groups them into 12 responsibilities.
- **Why it matters:** every feature change edits the same object and its observation graph; a change to vault switching can break a drawing, a recording or a plugin; nothing below it can be tested without a real vault folder, a real `UserDefaults.standard` and real WebKit/AVFoundation objects (part 3.1).
- **Fix direction:** split along part 3.3: an `OpenVault` per vault, `TabWorkspace`, `SearchModel`, `FileOperationsModel`, `AttachmentInserter`, `RecordingCoordinator`, `PresentationRouter`; the remaining `WorkspaceModel` routes events and owns no storage keys. The "more than ~15 stored properties needs a recorded reason" rule fits Swift well here; `@Observable` makes the cost of a large type concrete because every view reading any property re-evaluates through it.

#### SRP-ARCH-02 `GraphiteUI` is one module holding every feature, every platform bridge, the plugin runtime and the composition root
- **Severity:** Medium
- **Evidence:** 153 Swift files and 46,252 code lines (reconnaissance), more than half the app's 80,841; it imports SwiftUI, UIKit (55 files), AppKit (22), WebKit ([CommunityPluginHost.swift:4](../../../Sources/GraphiteUI/CommunityPluginHost.swift#L4), [ThemeTokenResolver.swift:3](../../../Sources/GraphiteUI/ThemeTokenResolver.swift#L3)), MapKit ([BaseMapView.swift:2](../../../Sources/GraphiteUI/BaseMapView.swift#L2), [NotesMapView.swift:2](../../../Sources/GraphiteUI/NotesMapView.swift#L2)), PDFKit (15 files, e.g. [PDFSession.swift:3](../../../Sources/GraphiteUI/PDFSession.swift#L3)), PencilKit (14, e.g. [HistoryCanvasView.swift:3](../../../Sources/GraphiteUI/HistoryCanvasView.swift#L3)), MediaPlayer, QuickLook, PhotosUI, Textual and every Graphite module (import grep); it carries the plugin runtime's JavaScript and the theme resolver's resources ([Package.swift:33-37](../../../Package.swift#L33-L37)) and the public entry points `GraphiteRootView`, `GraphiteMacScenes`, `GraphiteCommands`, `GraphiteDiagnostics`, `GraphiteVoiceDownloads`.
- **Why it matters:** any edit to any feature rebuilds and re-tests the whole UI; internal types are visible everywhere, so features reach into each other (`MediaFileKind` defined in `MarkdownPreview.swift` and used by panes, canvas cards and conflict sheets: [MarkdownPreview.swift:232](../../../Sources/GraphiteUI/MarkdownPreview.swift#L232), [WorkspacePanes.swift:538](../../../Sources/GraphiteUI/WorkspacePanes.swift#L538), [CanvasCardViews.swift:263](../../../Sources/GraphiteUI/CanvasCardViews.swift#L263), [ConflictVersionsSheet.swift:347](../../../Sources/GraphiteUI/ConflictVersionsSheet.swift#L347)); the change hotspots (`NativeMarkdownEditor.swift` 41 commits, `MarkdownPane.swift` 36, `WorkspaceModel.swift` 29) all sit in this module.
- **Fix direction:** cut feature modules along the area boundaries (part 7): `GraphiteShell`, `GraphiteMarkdownEditing`, `GraphiteReading`, `GraphitePDF`, `GraphiteInk`, `GraphiteCanvas`, `GraphiteBases`, `GraphiteReadAloud`, `GraphitePlugins`, with shared view vocabulary in `GraphiteDesign`. The rule "split by responsibility, never by size" holds; here the responsibilities already exist as areas.

#### SRP-ARCH-03 `GraphiteCore` mixes pure Obsidian-format policy with file, network and keychain-adjacent I/O
- **Severity:** Medium
- **Evidence:** Core performs file I/O through `FileManager.default` (`VaultStore`, `AtomicFileWriter`, `FileRecoveryStore` in Application Support: [FileRecovery.swift:40-41](../../../Sources/GraphiteCore/FileRecovery.swift#L40-L41), `RecordingRecovery` in Application Support: [RecordingRecovery.swift:53-54](../../../Sources/GraphiteCore/RecordingRecovery.swift#L53-L54)) and network I/O with `URLSession.shared` as a default argument ([ObsidianThemes.swift:131](../../../Sources/GraphiteCore/ObsidianThemes.swift#L131), [CommunityPluginInstaller.swift:48](../../../Sources/GraphiteCore/CommunityPluginInstaller.swift#L48), [CommunityPluginNetworkRequest.swift:27](../../../Sources/GraphiteCore/CommunityPluginNetworkRequest.swift#L27)).
- **Why it matters:** "Core" reads as the pure layer, yet a test of a theme installer or a recovery store touches the real network or the real Application Support folder; the pure parsers (search syntax, Bases, Markdown semantics) cannot be shipped or tested without the I/O types beside them.
- **Fix direction:** keep `GraphiteCore` pure (values, parsers, policies, planners); move `VaultStore`, `AtomicFileWriter`, `FileRecoveryStore`, recovery folders and the three network clients into a `GraphiteStorage` module (and `GraphiteNetwork` or Apple adapters for URLSession) with the session injected.

#### SRP-ARCH-04 Presentation state is split between the root view and the workspace, as a set of booleans and optionals
- **Severity:** Medium
- **Evidence:** the root view owns 14 `@State` values including `showsSettings`, `showsTabSwitcher`, `activePalette`, `creation` ([GraphiteRootView.swift:10-34](../../../Sources/GraphiteUI/GraphiteRootView.swift#L10-L34)); the workspace owns `isGraphPresented`, `isMapPresented`, `isVaultManagerPresented`, `fileRecoveryRequest`, `conflictVersionsRequest`, `drawingEditorRequest`, `viewedImage`, `recordingRecoveryOffer`, `pendingMove`, `pendingDeletion`, `fileSheet`, `errorMessage`, `notice` ([WorkspaceModel.swift:31-35](../../../Sources/GraphiteUI/WorkspaceModel.swift#L31-L35), [:112-115](../../../Sources/GraphiteUI/WorkspaceModel.swift#L112-L115), [:150-172](../../../Sources/GraphiteUI/WorkspaceModel.swift#L150-L172)); the plugin host owns `isPanelPresented` ([CommunityPluginHost.swift:181](../../../Sources/GraphiteUI/CommunityPluginHost.swift#L181)); Settings closes and reopens the vault manager through a third flag ([GraphiteRootView.swift:106-109](../../../Sources/GraphiteUI/GraphiteRootView.swift#L106-L109)).

#### SRP-ARCH-05 Switching vaults is a hand-maintained list of resets that every feature must remember to join

- **Evidence:** about 25 assignments and calls at [WorkspaceModel.swift:303-323](../../../Sources/GraphiteUI/WorkspaceModel.swift#L303-L323) reset tabs, caches, retention, conflicts, search and plugin views, and rebind a singleton ([:309](../../../Sources/GraphiteUI/WorkspaceModel.swift#L309)); removing a vault is a second hand list ([:244-258](../../../Sources/GraphiteUI/WorkspaceModel.swift#L244-L258)) that names five stores (file recovery, index, plugins, three keys, places).

## 7. Blueprint for this area

### 7.1 Target module layout

| Module | Single responsibility | May import | Must not import |

| `GraphiteIndex` | Disposable SQLite cache and queries | Core, Storage, GRDB | UI frameworks, Apple adapters |
| `GraphiteApple` | Platform adapters: folder access, PDFKit, PencilKit, AVFoundation, Vision, keychain, diagnostics | Core, Storage | SwiftUI, Index, UI modules |

| `GraphiteDesign` | Shared SwiftUI vocabulary: theme tokens, chrome, `MessageAlert`, icons from descriptors | Core, SwiftUI | feature modules |

Cuts this layout needs, from the import graph: move `SearchSortOrder`, `PaperTemplate`, `PaperSpecification`, `CameraPosition` into Core (DIP-ARCH-05); move `MediaFileKind` into `DocumentKind` (LSP-ARCH-01); move `VaultStore` and friends out of Core (SRP-ARCH-03); give the plugin host a `PluginHostEnvironment` port instead of the workspace (part 3.4); make every view take a narrow model (ISP-ARCH-01).

### 7.2 Composition root and state ownership

- **`AppEnvironment`** (built once in `GraphiteApp.init`, never in a view initializer): `DeviceStateStore` (over `UserDefaults.standard` in the app, a suite per test), `Clock`, `VaultLocator`, `VaultIndexFactory`, recorder, read-aloud services, diagnostics, `PencilToolbox`, image caches, `EmbeddedPDFSessions`, the feature registry (`DocumentKindDescriptor`s, `WorkspaceCommand`s, `VaultPathMoveObserver`s, `VaultLifecycleObserver`s), and a launch mode (`.app`, `.voiceBenchmark`, `.hostedTests`) parsed once from the process arguments.
- **`WorkspaceModel.init(environment:)`**: holds the router and the current `OpenVault?`; on the Mac the delegate receives it from the scene's environment, not through a static weak var.
- **`OpenVault`** (one per open vault): folder access, store, index, monitor, file recovery, settings, indexing controller, external-change debouncer, conflict checks, and every vault-scoped presentation request. Switching vaults builds the new one, asks the current one to close (save with errors surfaced, plugins unload), then replaces it.
- **`DeviceStateKey` registry**: one declaration per key from part 8.2 with name, value type, default, encoding, scope (`global`, `perVault`) and version. Per-vault keys are enumerated, so vault removal is `deviceState.removeAll(forVault:)`. `@AppStorage` is allowed only through a registry-generated key and default.
- **Errors**: typed per area, one `ErrorPresenter` in `GraphiteShell` deciding alert vs banner and wording from a string catalogue.

### 7.3 Ordered steps (each leaves the app building and behaving the same)

1. Add `GraphiteTestSupport` (temporary vault, isolated `UserDefaults(suiteName:)`, `waitUntil` with a deadline, the conflict-store contract suite) and move `TestConflictVersionStore` there; fix its two divergences.
2. Introduce the `DeviceStateKey` registry with the exact key names of part 8.2; route `GraphitePreferences`, `VaultLibrary`, workspace keys and `@AppStorage` sites through it without changing names, defaults or encodings. Add golden tests per key.
3. Give `WorkspaceModel` an initializer taking the collaborators it builds today (default values kept for one release of the code), then build them in `GraphiteApp.init` and pass them down; remove the `@State` construction in `GraphiteRootView`/`GraphiteMacScenes`.
4. Replace the two `UserDefaults` message channels (DIP-ARCH-04) with model intents.
5. Stop swallowing: the vault-switch save (BUG-ARCH-04), the Mac quit save with a prompt (BUG-ARCH-02), safety copies (CC-ARCH-02).
6. Unify media classification and the link resolver behind one policy each, with contract tests (fixes BUG-ARCH-01, BUG-ARCH-05).
7. Extract `OpenVault` and move the reset list into its construction; capture `FolderAccess` in drawing requests (fixes BUG-ARCH-03); add vault-removal through the registry (fixes BUG-ARCH-06, BUG-ARCH-07 with a per-vault positions key).
8. Introduce `DocumentKindDescriptor` and `DocumentSession`; move the five `default:` switches to descriptor lookups.
9. Generate palette, menu-bar and bar commands from one `WorkspaceCommand` enum with stable raw values.
10. Move value types into Core, I/O out of Core, then cut feature modules one area at a time (smallest first: Canvas, Bases, ReadAloud, Plugins, PDF/Ink, Markdown).
11. Add CI running `swift test` and the hosted suite in a test launch mode.
