# Rule status

Snapshot: b13dec3 (main, 2026-10-18).

This document assesses each of the 108 rules `FR-01` to `FR-108` of [rewrite-foundations.md](rewrite-foundations.md) section 11 against the code of the snapshot. It does not count closed findings. A rule is judged by what the code does today, checked with the mechanical search named in the row where the rule has one, and with the finding IDs of its source principle rules plus a place that already meets it where the rule is structural.

**Totals: 0 Supported, 62 Partial, 43 Open, 3 Not reassessed, of 108 rules.**

Closing findings and meeting the rules are different measures. This document never states a percentage of compliance; a rule is Supported only when the code meets it, whatever the finding count says.

No rule is Supported at the snapshot: for every rule at least one checked site breaks it. The Partial rules that are closest to Supported name a short list of sites: `FR-45` (5 functions with more than 6 parameters), `FR-71` (2 `try!` and 3 force unwraps), `FR-31` (one protocol extension), `FR-84` (a few test files), `FR-22` (the Swift receivers). The Open rules mostly lack the mechanism the rule names (`AppEnvironment`, the key registry, the shared primitives, the test-support target, contract suites, CI).

## How a status is decided

| Status | Meaning |
| --- | --- |
| **Supported** | Every site checked meets the rule. The evidence says what was searched and how. |
| **Partial** | A compliant pattern exists and is used in some places; other places break the rule. Both are cited. |
| **Open** | The mechanism or owner the rule needs does not exist, or the sites checked break it with no compliant model to extend. A place that already points the way is still cited. |
| **Not reassessed** | The snapshot cannot show it. The row says why. |

## Method

- **Searches.** Run with ripgrep over production Swift (`Sources/**/*.swift` and `App/GraphiteApp.swift`, 321 files) and over test Swift (`Tests/**` and `App/Tests/**`, 208 files). A count is "lines / files" of raw matches including comments, so it can differ by a few from the stripped counts of [metrics.md](metrics.md) (for example `\btry\?` is 624 lines here and 628 occurrences there). Where a row says "metrics.md" it reuses that page's number and regular expression instead of repeating the search.
- **Stored properties per class** come from a script that brace-matches every `class` and `actor` (216 in production) and counts the `var` and `let` members declared directly in the body, without `static` and without computed properties.
- **Findings** cite [findings-index.md](findings-index.md) IDs; the evidence is in the area documents ([areas/](areas/)) and [architecture](cross-cutting/architecture.md). Places that already meet a rule come from the "What to keep" sections of those documents and were re-read in the snapshot.
- **Names that do not exist yet.** `AppEnvironment`, `ApplicationClock`, `DeviceStateKey`, `DeviceStateStore`, `StaticPattern`, `Debouncer`, `LatestRequest`, `withTimeout`, `BoundedMarkdownParser`, `DocumentFileAccess`, `ErrorPresenter`, `HostChannel`, `HostMessageRouter`, `VaultPathMoveObserver`, `VaultLifecycleObserver`, `MemoryReleasing`, `GraphiteTestSupport`, `ManualClock`, `TemporaryVault`, `FailingVaultFiles` and `awaitCondition` occur in no file of `Sources/`, `App/` or `Tests/` (search `\bName\b`, 0 files each). Rules that name one of them are Open for that part.
